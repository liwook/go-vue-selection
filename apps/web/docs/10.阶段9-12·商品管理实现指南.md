## 0. 后端契约总览 {#s0}

所有请求走 `src/utils/request.ts`，响应拦截器在 `code===200` 时返回整个包裹对象 `{ code, data, message }`（见 `request.ts:46`）。因此与阶段 6~8 **完全一致**：

- 接口层函数返回类型都是 `ResponseData<T>`，页面取数一律 `res.data`；
- 非 200 已在拦截器 `ElMessage.error` 并 reject，页面 `try/catch` 空处理即可；
- token 由请求拦截器从 `localStorage.token` 自动注入 `headers.token`，接口层无需关心。

⚠️ **本篇全部接口都对接真实后端**（`.env.development` 的 `VITE_API_BASE_URL`），且全部走 axios 拦截器——**只有文件上传的 `el-upload` 组件例外**（见 9.2）。

### 0.1 各模块接口清单

**分类 `/api/v1/product/category1` `/category2/{category1Id}` `/category3/{category2Id}`**（GET，返回 `Category1[]/2/3`）；新增接口 `/category2` `/category3`（POST，父级 ID 放 body，后端生成分类 ID 并返回新建信息）

| 方法 | 路径                              | 入参                                   | 返回 `data`   | 作用                                   |
| ---- | --------------------------------- | -------------------------------------- | ------------- | -------------------------------------- |
| GET  | `/api/v1/product/category1`        | —                                      | `Category1[]` | 一级分类                               |
| GET  | `/api/v1/product/category2/{c1Id}` | path                                   | `Category2[]` | 二级分类                               |
| GET  | `/api/v1/product/category3/{c2Id}` | path                                   | `Category3[]` | 三级分类                               |
| POST | `/api/v1/product/category2`        | body `ParamC2Create{category1Id,name}` | `Category2`   | 新增二级分类（后端生成 `category2Id`） |
| POST | `/api/v1/product/category3`        | body `ParamC3Create{category2Id,name}` | `Category3`   | 新增三级分类（后端生成 `category3Id`） |

**品牌 `/api/v1/product/trademark`**

| 方法   | 路径                       | 入参                               | 返回 `data`                                         | 作用                          |
| ------ | -------------------------- | ---------------------------------- | --------------------------------------------------- | ----------------------------- |
| GET    | `/trademark`               | query `page,limit`                 | `ResponseTmList{ records:Trademark[]; total; ... }` | 分页列表                      |
| POST   | `/trademark`               | body `{ tmName, logoUrl }`（必填） | `null`                                              | 新增品牌                      |
| PUT    | `/trademark/{trademarkId}` | body `{ id, tmName, logoUrl }`     | `null`                                              | 修改品牌（路径 id = body.id） |
| DELETE | `/trademark/{trademarkId}` | path                               | `null`                                              | 删除品牌                      |
| GET    | `/trademark/all`           | —                                  | `Trademark[]`                                       | 全量品牌（SPU 选品牌用）      |

> `Trademark`：`id`（主键，后端已收敛为小写 `id`，不再有冗余大写 `ID`）、`tmName`、`logoUrl`、`createTime`、`updateTime`。

**文件上传 `/api/v1/product/file/upload`**（POST，header `token` + formData `file`）→ 返回 `ResponseData<string>`，`data` 即图片 URL 字符串。

**平台属性 `/api/v1/product/attr`**

| 方法   | 路径                         | 入参                              | 返回 `data` | 作用                                   |
| ------ | ---------------------------- | --------------------------------- | ----------- | -------------------------------------- |
| GET    | `/attr/{c1Id}/{c2Id}/{c3Id}` | path 三级分类                     | `Attr[]`    | 取某三级分类下的属性及属性值           |
| POST   | `/attr`                      | body `Attr`（含 `attrValueList`） | `null`      | **新增或修改**（同一接口，有 id 即改） |
| DELETE | `/attr/{attrId}`             | path                              | `null`      | 删除属性                               |

> `Attr`：`id?`、`attrName`、`categoryId`（三级分类 id，string）、`categoryLevel`（**提交时固定传 `3`**，见 10.3 代码与学习要点）、`attrValueList: AttrValue[]`；`AttrValue`：`id?`、`attrId?`、`valueName`。
>
> 注：早期约定"无需传 `categoryLevel`、由后端根据 `categoryId` 推断"与代码实现不符——当前实现 `10.3` 的 payload 显式带 `categoryLevel: 3`，请以代码为准。

**基础销售属性 `/api/v1/product/baseSaleAttr`**（GET）→ `SaleAttr[]`（SPU 阶段「添加销售属性」的下拉来源）。

**SPU `/api/v1/product/spu`**

| 方法   | 路径                    | 入参                           | 返回 `data`                                    | 作用                   |
| ------ | ----------------------- | ------------------------------ | ---------------------------------------------- | ---------------------- |
| GET    | `/spu`                  | query `page,limit,category3Id` | `ResponseSpuList{ records:Spu[]; total; ... }` | 分页列表（按三级分类） |
| POST   | `/spu`                  | body `Spu`                     | `null`                                         | 新增 SPU               |
| PUT    | `/spu/{spuId}`          | body `Spu`（含 id）            | `null`                                         | 修改 SPU               |
| DELETE | `/spu/{spuId}`          | path                           | `null`                                         | 删除 SPU               |
| GET    | `/spu/{spuId}/images`   | path                           | `SpuImage[]`                                   | 该 SPU 的图片列表      |
| GET    | `/spu/{spuId}/saleAttr` | path                           | `SpuSaleAttr[]`                                | 该 SPU 的销售属性及值  |
| GET    | `/spu/{spuId}/sku`      | path                           | `ResponseSkuInfo[]`                            | 该 SPU 下的 SKU 列表   |

> `Spu`：`id?`、`category3Id`、`spuName`、`description`、`tmId`、`spuImageList: SpuImage[]`、`spuSaleAttrList: SpuSaleAttr[]`。
> `SpuImage`：`id?`、`imgName?`、`imgUrl`。`SpuSaleAttr`：`id?`、`baseSaleAttrId?`、`saleAttrName`、`spuId?`、`spuSaleAttrValueList: SaleAttrValue[]`。`SaleAttrValue`：`id?`、`baseSaleAttrId?`、`saleAttrValueName`、`spuId?`。

**SKU `/api/v1/product/sku`**

| 方法   | 路径                      | 入参               | 返回 `data`                                                    | 作用         |
| ------ | ------------------------- | ------------------ | -------------------------------------------------------------- | ------------ |
| GET    | `/sku`                    | query `page,limit` | `ResponseSkuInfoList{ records:ResponseSkuInfo[]; total; ... }` | SKU 分页列表 |
| POST   | `/sku`                    | body `SkuInfo`     | `null`                                                         | 新增 SKU     |
| GET    | `/sku/{skuId}`            | path               | `ResponseSkuInfo`                                              | SKU 详情     |
| DELETE | `/sku/{skuId}`            | path               | `null`                                                         | 删除 SKU     |
| PUT    | `/sku/{skuId}/onsale`     | path               | `null`                                                         | 上架         |
| PUT    | `/sku/{skuId}/cancelsale` | path               | `null`                                                         | 下架         |

> `SkuInfo`（新增/编辑提交体）：`category3Id`、`spuID`(注意大写 D)、`tmId`、`skuName`、`priceCent`(价格，单位：分，int)、`weightMg`(重量，单位：毫克，int)、`skuDesc`、`skuAttrValueList: SkuAttrValueDTO[]`、`skuSaleAttrValueList: SkuSaleAttrValueDTO[]`、`skuImageList: SkuImgDTO[]`。
> ⚠️ **价格/重量单位为「分/毫克」**：前端表单输入习惯是「元/克」，提交 SKU 前需换算（`priceCent = 元 × 100`、`weightMg = 克 × 1000`），后端返回列表/详情也是「分/毫克」，前端展示时再反向换算成「元/克」。
> `ResponseSkuInfo`（列表项/详情，在 `SkuInfo` 基础上多 `id`/`isSale`/`createTime`/`updateTime`）。
> DTO：`SkuAttrValueDTO{ attrId, attrName?, valueId, valueName }`、`SkuSaleAttrValueDTO{ saleAttrId, saleAttrName?, saleAttrValueId, saleAttrValueName }`、`SkuImgDTO{ imgName?, imgUrl, isDefault?, spuImgId? }`。
>
> ⚠️ **默认图片没有独立字段**：后端不返回也不读取 `skuDefaultImg`，某一图片是否为默认图由 `skuImageList[].isDefault === '1'` 标识。提交时把选中的那张 `isDefault` 置 `'1'`、其余 `'0'`；展示时取 `skuImageList.find(i => i.isDefault === '1')?.imgUrl`，找不到再兜底 `skuImageList[0]?.imgUrl`。

### 0.2 贯穿四阶段的两个大坑（务必先读）

1. **`el-upload` 不走 axios 拦截器**：组件自己发请求，所以 `:action` 必须拼**全 URL**（`import.meta.env.VITE_API_BASE_URL + '/api/v1/product/file/upload'`），`:headers` 必须手动带 `{ token: localStorage.getItem('token') }`。否则 401/图片传不上去。详情见 9.2。
2. **SKU 的 SPU 关联字段是 `spuID`（大写 D）**：提交 SKU 时 body 必须带 `spuID`（不是 `spuId`）。类型里已严格写为 `spuID: number`。

### 0.3 开发环境图片加载（Vite 代理配置） {#s0-3}

品牌 Logo、SPU/SKU 图片等静态资源由后端直接返回 URL（如 `/static/img/sph/20240909/xiaomi.png`），前端 `<img>` 直接拿该 URL 渲染，**不走 axios 拦截器、也不走 `baseURL`**，所以浏览器实际请求的是 `http://localhost:5173` 当前 dev 服务下的路径。

为了让 dev 环境能正确取到后端图片与 API，需在 `vite.config.ts` 里配置开发服务器代理，把 `/admin` 开头的请求（含图片静态资源）转发给后端：

```ts
// vite.config.ts（server.proxy 部分）
server: {
  proxy: {
    '/admin': {
      target: env.VITE_API_BASE_URL, // 复用 .env.development 的 VITE_API_BASE_URL（http://localhost:9000）
      changeOrigin: true,
      // 本仓库后端接口前缀就是 /admin，无需 rewrite 剥离前缀
    },
  },
},
```

> ⚠️ 本仓库后端接口前缀为 `/admin`（**无 `/api` 前缀**），不要照搬旧的 `/api` 写法。后端已配 CORS（`AllowOrigins: *`），联调也可不代理直连；代理仅是 dev 好实践。

**要点**：

- 该代理**仅 `pnpm run dev` 时生效**；`pnpm run build:prod` 打包后此配置被忽略，生产环境由 Nginx 负责转发（见 [`05`](./05.SPA路由与部署·哈希模式vs历史模式.md)）。
- 此代理同时兼容图片请求与 API 请求（API 走 axios 的 `baseURL` 全路径直连，并不经过 Vite proxy；而图片 `<img>` 若使用相对路径 `/admin/...` 正好命中代理）。
- **改完 `vite.config.ts` 必须重启 dev 服务**（`Ctrl+C` → `pnpm run dev`），热更新不会重新加载配置。
- 若重启后仍不显示，需确认后端该图片路径（如 `/api/v1/product/...` 静态资源）下文件确实存在，以及 `logoUrl` 字段返回的路径与后端实际存放路径一致。

```ts
// src/api/product/trademark/index.ts
import request from '@/utils/request'
import type {
  TmListResponse,
  AllTmResponse,
  TmSaveForm,
  TmUpdateForm,
  TmSaveResponse,
} from '@/api/product/type'

const BASE = '/api/v1/product/trademark'
const URL = {
  LIST: BASE, // GET 分页 ?page&limit；POST 新增
  ALL: `${BASE}/all`, // GET 全量（SPU 选品牌用）
  DETAIL: (id: number) => `${BASE}/${id}`,
}

export const reqGetTmList = (page: number, limit: number) =>
  request.get<ResponseTmList, TmListResponse>(URL.LIST, { params: { page, limit } })

export const reqGetAllTm = () => request.get<Trademark[], AllTmResponse>(URL.ALL)

export const reqAddTm = (data: TmSaveForm) =>
  request.post<unknown, TmSaveResponse, TmSaveForm>(URL.LIST, data)

// 修改：路径 id 取 body.id（与 ParamTmUpdate.id 一致）
export const reqUpdateTm = (data: TmUpdateForm) =>
  request.put<unknown, TmSaveResponse, TmUpdateForm>(URL.DETAIL(data.id), data)

export const reqRemoveTm = (id: number) => request.delete<unknown, TmSaveResponse>(URL.DETAIL(id))
```

### 10.2 共享组件 `CategorySelect` {#s10-2}

#### 为什么 attr 页和 spu 页都要用它？

因为这两类数据都挂在**三级分类**之下，必须先选好一/二/三级分类，才能拿到对应的业务数据：

- **属性管理（attr 页）**：接口是 `URL.LIST(c1, c2, c3)`（见 578 行），按三级分类查属性，没选三级分类就没法列属性。
- **SPU 商品（spu 页）**：一个 SPU 也归属到某个三级分类下，建 SPU 前同样要先选分类。

「先选三级分类、再做主体数据操作」是这两个页面的公共前置步骤。把这段选择逻辑抽成 `CategorySelect` 共享组件后，两个页面都只需 `<CategorySelect v-model:c1Id=... v-model:c2Id=... v-model:c3Id=... />`，避免各写一遍联动逻辑。

#### 什么是「三级分类联动」？

电商商品类目分三层、层级依赖：

```text
一级分类（如：服装）→ 二级分类（如：男装）→ 三级分类（如：T恤）
```

「联动」= 级联选择：选了一级，二级下拉才加载该一级下的子项；选了二级，三级才加载。上级没选，下级就禁用（模板里 `:disabled="disabled || !c1Id"` 就是这个效果）。最终拿到 `c1Id / c2Id / c3Id` 三个 id 去查数据。

#### 什么是 `defineModel`？

Vue 3.4 引入、3.5 稳定的**编译宏**，用来做组件的双向绑定，替代以前 `props + emit('update:xxx')` 的样板代码。这里用三个 model：

```ts
const c1Id = defineModel<string | undefined>('c1Id')
const c2Id = defineModel<string | undefined>('c2Id')
const c3Id = defineModel<string | undefined>('c3Id')
// ⚠️ el-option 的 :value 必须用后端真实字段 category1Id / category2Id / category3Id
//    若写成 c.id 会导致选项 value=undefined，下拉选不中、下级接口拿不到 id
// ⚠️ onC1/onC2 直接接收 el-select 的 change 事件参数，避免 defineModel 同步延迟导致 load 时 c1Id/c2Id 还是旧值
```

父组件用 `v-model:c1Id="xxx"` 即可双向绑定；子组件内部改 `c1Id.value`，父组件自动同步——不用自己写 `props` 接收 + `emit('update:c1Id')`，比老写法省了一半代码。

```ts
import request from '@/utils/request'
import type {
  ResponseSkuInfo,
  ResponseSkuInfoList,
  SkuInfo,
  SkuListResponse,
  SkuDetailResponse,
  SkuSaveResponse,
} from '@/api/product/type'

const BASE = '/api/v1/product/sku'
const URL = {
  LIST: BASE, // GET ?page&limit
  DETAIL: (id: number) => `${BASE}/${id}`,
  CANCEL: (id: number) => `${BASE}/${id}/cancelsale`,
  ONSALE: (id: number) => `${BASE}/${id}/onsale`,
}

export const reqGetSkuList = (page: number, limit: number) =>
  request.get<ResponseSkuInfoList, SkuListResponse>(URL.LIST, { params: { page, limit } })

export const reqAddSku = (data: SkuInfo) =>
  request.post<unknown, SkuSaveResponse, SkuInfo>(URL.LIST, data)

export const reqGetSkuDetail = (id: number) =>
  request.get<ResponseSkuInfo, SkuDetailResponse>(URL.DETAIL(id))

export const reqRemoveSku = (id: number) => request.delete<unknown, SkuSaveResponse>(URL.DETAIL(id))

// 上架 / 下架（PUT，路径参数）
export const reqOnSale = (id: number) => request.put<unknown, SkuSaveResponse>(URL.ONSALE(id))
export const reqCancelSale = (id: number) => request.put<unknown, SkuSaveResponse>(URL.CANCEL(id))
```

```vue
    if (row.isSale === 1) await reqCancelSale(row.id!)
    else await reqOnSale(row.id!)
    // 直接本地更新行状态，避免整表刷新
    row.isSale = row.isSale === 1 ? 0 : 1
    ElMessage.success('操作成功')
  } catch {
    // 拦截器已提示错误
  }
}

function handleSizeChange() {
  pageNo.value = 1
  getSkuList()
}

async function showDetail(row: ResponseSkuInfo) {
  try {
    detail.value = (await reqGetSkuDetail(row.id!)).data
    detailVisible.value = true
  } catch {}
}

async function removeSku(row: ResponseSkuInfo) {
  try {
    await reqRemoveSku(row.id!)
    ElMessage.success('删除成功')
    if (skuList.value.length === 1 && pageNo.value > 1) pageNo.value--
    getSkuList()
  } catch {
    // 拦截器已提示错误
  }
}

// 取默认图：优先 isDefault==='1'，兜底第一张
function getDefaultImgUrl(list?: { imgUrl: string; isDefault?: string }[]) {
  if (!list?.length) return ''
  return list.find((i) => i.isDefault === '1')?.imgUrl ?? list[0].imgUrl
}
```

## 学习要点总结 {#slearn}

| 要点                                             | 关键代码                                                                    | 说明                                                                                                               |
| ------------------------------------------------ | --------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| **四模块共用一套响应/类型约定**                  | `ResponseData<T>`（全局）+ `src/api/product/type.ts`（领域合一）            | 接口层只放函数，类型集中；URL 前缀统一 `/api/v1/product/*`                                                          |
| **接口层泛型不用 `any`**                         | `request.get<响应体, 返回R, 请求体D>`                                       | 与阶段 6~8 一致：第一参真实响应体，第二参 `R = ResponseData<...>`，第三参约束 body                                 |
| **`el-upload` 不走 axios 拦截器**                | `:action="\`${baseURL}/api/v1/product/file/upload\`"`+`:headers="{ token }"` | 组件自发包，必须拼全 URL、手动带 token；`on-success` 的 `res` 是原始 `{code,data,message}`，直接 `res.data` 取 URL |
| **SKU 的 SPU 关联字段是 `spuID`**                | `SkuInfo.spuID: number`                                                     | 提交 SKU 必须带 `spuID`（大写 D），写错字段名后端收不到                                                            |
| **attr 新增/修改同一接口**                       | `POST /attr`，body 带 `id` 即改                                             | `categoryId` 传三级分类 id、`categoryLevel` 固定 `3`                                                               |
| **三级分类联动抽组件**                           | `CategorySelect` + `defineModel` 双向绑定 c1/c2/c3                          | attr 页与 spu 页复用；切换一级清空二三级并重新拉取                                                                 |
| **SPU 单页多场景**                               | `scene` 切换 0 列表 / 1 SPU表单 / 2 SKU表单                                 | 避免多路由；SKU 表单依赖「当前三级分类属性 + SPU 销售属性 + SPU 图片」三份数据                                     |
| **UI 辅助字段不剔除也能提交**                    | `spuSaleAttrList` 上的 `edit`/`inputVal`                                    | 后端忽略未知字段；如需严格可在提交前 `map` 掉                                                                      |
| **上架/下架是 PUT 无 body**                      | `reqOnSale`/`reqCancelSale` → `request.put(url)`                            | 路径 `/sku/{id}/onsale`、`/cancelsale`                                                                             |
| **`ElMessage` 走自动导入 + 异步 try/catch 兜底** | 页面不 `import`，`catch { }` 空处理                                         | 非 200 已在拦截器 `ElMessage.error` 并 reject，catch 仅阻止后续流程（与阶段 6~8 一致）                             |

## 常见报错排查 {#serr}

| 现象                                    | 原因                                                                             | 解决                                                                                                                                                                                         |
| --------------------------------------- | -------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 品牌/SKU 图片传不上去，控制台 401       | `el-upload` 没带 token / action 不是全 URL                                       | `:action` 拼 `import.meta.env.VITE_API_BASE_URL + '/api/v1/product/file/upload'`；`:headers="{ token: localStorage.getItem('token') }"`                                                       |
| `on-success` 里 `res.data` 是 undefined | 把 el-upload 的 res 当成拦截器返回值                                             | el-upload 的 res 是原始 `{code,data,message}`，直接 `res.data` 取 URL 即可                                                                                                                   |
| 页面取数 `undefined`                    | 直接用了返回值当业务数据                                                         | 接口层返回包裹对象，取 `res.data`                                                                                                                                                            |
| 提交 SKU 后后端收不到 SPU 关联          | 字段写成 `spuId`（小写 d）                                                       | 改成 `spuID`（大写 D）                                                                                                                                                                       |
| 删除/更新报「字段不存在」               | 旧代码误用大写 `ID` 当主键（后端已移除该字段）                                   | 统一使用小写 `id`；若从旧文档复制需删掉残留的 `ID?` 字段声明                                                                                                                                 |
| 属性页/SPU 页列表空白                   | 三级分类没选满就调接口                                                           | `reqGetAttrList` / `reqGetSpuList` 必须传满 c1/c2/c3（`category3Id` 必填）                                                                                                                   |
| SPU 列表报「请求路径不存在」/ 404       | SPU 接口前缀写成了 `/api/v1/product`（少了 `/spu` 段）                            | 后端契约里 SPU 接口都在 `/api/v1/product/spu` 下；`src/api/product/spu/index.ts` 的 `BASE` 应为 `/api/v1/product/spu`（子资源路径自动带 `/spu`，`baseSaleAttr` 仍用独立字面量）                |
| 按钮图标空白/不显示                     | `el-button` 上写 `icon="Plus"` 这种**字符串**不会渲染；`<Plus />` 也未被自动导入 | 统一改用 `IconEp*` 组件：`<el-button><el-icon><IconEpPlus /></el-icon>文字</el-button>`；项目图标走 `unplugin-icons` + `@iconify-json/ep`，`IconEp*` 由模板标签触发自动导入，无需手写 import |
| 销售属性下拉重复或选不上                | `unUsedSaleAttr` 未排除已添加项                                                  | 用 `computed` 过滤 `spuSaleAttrList` 里已有的 `baseSaleAttrId`                                                                                                                               |
| `ElMessage` 弹窗纯白无样式              | 页面里手动 `import { ElMessage }`                                                | 删掉 import，交 AutoImport + ElementPlusResolver 自动导入                                                                                                                                    |
| SKU 上架/下架无反应                     | 误用 POST 或拼错路径                                                             | `PUT /sku/{id}/onsale` 与 `/cancelsale`，无 body，用 `request.put(url)`                                                                                                                      |
| `defineModel` 报找不到                  | Vue 版本 < 3.4                                                                   | 项目是 Vue 3.5，`defineModel` 稳定可用；若仍报错检查 `vite`/vue 版本或改用 props+emit                                                                                                        |
| 品牌/商品图片在 dev 环境裂图、请求 404  | `vite.config.ts` 未配置 `/api` 代理（图片 `<img>` 走相对路径，命中 Vite proxy）  | 配置 `server.proxy['/api']` 转发到 `VITE_API_BASE_URL` 并 `rewrite` 去掉 `/api` 前缀（见 0.3）；改完需重启 `pnpm run dev`；仍 404 再查后端 `/static/img/sph/...` 文件是否真实存在            |
