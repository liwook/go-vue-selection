## 0. 后端契约与前提 {#s0}

按钮权限的数据链路是：

```text
登录 → 路由守卫触发 getUserInfo() → userInfo.value.buttons = res.data.buttons
                                              │
                                              ▼
                          v-auth 指令在 mounted 时读取该数组做判断
```

**数据结构（以 `docs/api/swagger.json` 为准）**

`/api/v1/acl/user/info` 接口（swagger 中 `controller._ResponseUserInfo` → `model.ResponseUserInfo`）返回 `buttons` 字段，类型为 `string[]`，即按钮权限标识数组；前端 `src/api/user/type.ts` 的 `userinfoType` 与之对应，`getUserInfo()` 把它写进 `userInfo.value.buttons`。

> ⚠️ swagger 只声明 `buttons` 是「字符串数组」，**不列出具体标识值、也不描述账号差异**。`btn.Trademark.add`、`btn.Sku.updown` 这类命名（`btn.<模块>.<动作>`），以及 `admin` 返回全部标识、非 admin 按角色过滤，都是**后端约定 / 运行时行为**，**以 `console.log(userStore.userInfo.buttons)` 实际打印为准**。13.5 对照表按尚硅谷标准命名列出，若命名有出入，改指令值即可，结构不动。

## 阶段 13：按钮级权限 v-auth {#s13}

### 13.1 原理：Vue 自定义指令 + Pinia 取 buttons {#s13-1}

Vue 3 自定义指令有 `mounted / updated / unmounted` 等钩子。按钮级权限只需在元素「挂载到 DOM」那一刻判断一次：

1. 指令挂载（`mounted`）时，调用 `useUserStore()` 拿到 pinia 中的 `userInfo.buttons`；
2. 用 `binding.value`（模板里 `v-auth="'btn.Trademark.add'"` 的单引号字符串）作为「所需权限」；
3. 若 `buttons` 不含该值 → `el.remove()` 直接从 DOM 删掉这个按钮，效果等同于「该按钮不存在」。

为什么用 `mounted + el.remove()` 而不是 `v-if`/`v-show`？

- `v-if` 要在模板里写 `v-if="userStore.buttons.includes('...')"`，每个按钮都要重复取 store、引入 `useUserStore`，模板又臭又长；
- 自定义指令把判断逻辑收敛到一处（`auth.ts`），模板只留一个 `v-auth="xxx"`，语义清晰、可复用、零样板；
- `el.remove()` 是**物理移除**（不是 `display:none`），彻底杜绝「按钮在 DOM 里只是藏起来、用户仍能用 DevTools 改回来看见」的权限绕过隐患。

### 13.2 指令实现 `src/directives/auth.ts`【新增】 {#s13-2}

```ts
// src/directives/auth.ts
import type { Directive, DirectiveBinding } from 'vue'
import useUserStore from '@/store/modules/user'

// 自定义指令 v-auth：按钮级权限控制
// 用法：<el-button v-auth="'btn.Trademark.add'">添加品牌</el-button>
// 原理：元素挂载后从 pinia 读取 userInfo.buttons，
//       若不含指令值则直接 el.remove() 移除该 DOM（不渲染 = 无权限）
const auth: Directive<HTMLElement, string> = {
  mounted(el: HTMLElement, binding: DirectiveBinding<string>) {
    const userStore = useUserStore()
    // 保守策略：buttons 为空（未登录 / 信息未加载）时按「无权限」处理
    const buttons: string[] = userStore.userInfo.buttons ?? []
    const required = binding.value
    if (!buttons.includes(required)) {
      el.remove()
    }
  },
}

export default auth
```

> 泛型 `Directive<HTMLElement, string>`：第一个参数是被绑定元素的类型，第二个参数是 `binding.value` 的类型（这里是权限字符串）。这样模板里 `v-auth="xxx"` 传非字符串会被 TS 拦下。

### 13.3 全局注册 `src/main.ts` {#s13-3}

在 `createApp` 之后、挂载之前，用 `app.directive('auth', auth)` 注册。指令名 `auth` 决定模板里写 `v-auth`。

```ts
// src/main.ts
import 'element-plus/theme-chalk/dark/css-vars.css'
import { createApp } from 'vue'
import './style.css'
import App from './App.vue'
import SvgIcon from '~virtual/svg-component'
import router from '@/router'
import pinia from '@/store'
import auth from '@/directives/auth' // ← 新增：引入指令

// hash 模式下路径纠正（原有逻辑保留）
normalizePathnameToHash()

const app = createApp(App)
app.component('SvgIcon', SvgIcon)
app.use(router)
app.use(pinia)
app.directive('auth', auth) // ← 新增：全局注册 v-auth
app.mount('#app')
```

> **Pinia 时机保证**：指令只在 `mounted` 钩子里调用 `useUserStore()`，而 `mounted` 发生在组件被插入 DOM 时——此时 `app.use(pinia)` 早已执行，pinia 已就绪。所以即便把 `app.directive(...)` 写在任何位置（只要在 `mount('#app')` 之前），指令内部读 store 都不会报「[vue] getActivePinia was called with no active Pinia」。

### 13.4 模板用法 `v-auth="'btn.xxx'"` {#s13-4}

注意**必须写两对引号**：外层是 Vue 绑定（`v-auth="..."`），内层是 JS 字符串字面量，所以值是 `'btn.Trademark.add'`（单引号串）。漏掉内层引号会变成「取名为 `btn.Trademark.add` 的变量」，运行时 `undefined` → 按钮全被移除。

```vue
<!-- 图标用 IconEp* 组件（来自 @iconify-json/ep，经 unplugin-icons 自动导入，无需手写 import；
     注意不要用字符串 icon="Plus"，详见文末「常见报错排查」的「Element 图标不显示（纯文本）」） -->
<!-- 普通按钮：直接挂 -->
<el-button type="primary" v-auth="'btn.Trademark.add'" :icon="IconEpPlus" @click="openAdd">
  添加品牌
</el-button>

<!-- 删除按钮被 el-popconfirm 包着，v-auth 挂法见 13.6 -->
<el-popconfirm
  v-auth="'btn.Trademark.remove'"
  :title="`确定删除 ${row.tmName} ?`"
  @confirm="removeTm(row)"
>
  <template #reference>
    <el-button size="small" type="danger" :icon="IconEpDelete">删除</el-button>
  </template>
</el-popconfirm>
```

### 13.5 各页面按钮 × 权限标识对照表 {#s13-5}

把下列 `v-auth` 加到对应页面的 `<template>` 即可。表格「位置」一栏用「按钮所在函数 / 元素」定位，与当前仓库代码对应（不写死行号，避免文件变动后失效）。

> 所有「删除」按钮的 `v-auth` 都挂在**外层 `<el-popconfirm>`** 上（位置列标 `el-popconfirm` 即指此），**不要**挂内层 `<el-button>`——为何如此见 [13.6 坑 1](#s13-6)。

#### 实操示例：对照表怎么落地成代码（以品牌管理为例）

对照上表第一行「品牌管理」，实际操作就是给模板里的按钮**加上 `v-auth="'btn.xxx'"`**，其余原样保留（`@click`、`el-popconfirm` 结构都不动）：

```vue
<!-- src/views/product/trademark/index.vue · <template> 片段 -->
<el-card>
  <!-- ① 添加品牌：直接挂 v-auth -->
  <el-button type="primary" :icon="IconEpPlus"
             v-auth="'btn.Trademark.add'" @click="openAdd">
    添加品牌
  </el-button>

  <el-table :data="tmList">
    <el-table-column label="操作">
      <template #default="{ row }">
        <!-- ② 编辑：直接挂 v-auth -->
        <el-button size="small" type="primary" :icon="IconEpEdit"
                   v-auth="'btn.Trademark.update'" @click="openEdit(row)">
          编辑
        </el-button>

        <!-- ③ 删除：v-auth 挂在外层 el-popconfirm 上 -->
        <el-popconfirm
          v-auth="'btn.Trademark.remove'"
          :title="`确定删除 ${row.tmName} ?`"
          @confirm="removeTm(row)"
        >
          <template #reference>
            <el-button size="small" type="danger" :icon="IconEpDelete">删除</el-button>
          </template>
        </el-popconfirm>
      </template>
    </el-table-column>
  </el-table>
</el-card>
```

要点：

- 三处 `v-auth` 的值，正好对应表格「权限标识」列（`btn.Trademark.add` / `update` / `remove`）；
- 效果：`admin` 账号 `buttons` 含全部标识 → 三个按钮都显示；非 `admin` 缺 `btn.Trademark.remove` → 「删除」按钮被物理移除，其余照常；
- 其余页面（属性 / SPU / SKU / 用户 / 角色 / 权限）**照此葫芦画瓢**：找到表格「位置」列对应的按钮，按对应「权限标识」加一行 `v-auth` 即可，无需改动任何业务逻辑。

### 13.6 避坑：`el-popconfirm` 套指令 / Pinia 时机 {#s13-6}

#### 坑 1：删除按钮的 `v-auth` 挂在哪？

删除按钮被 `el-popconfirm` 的 `#reference` 插槽包着。有两种挂法：

- ❌ 挂在内层 `<el-button>` 上：`el.remove()` 只删掉按钮，外层 `el-popconfirm` 失去触发源，会留下一个「没有扳机的气泡确认框」，控制台可能告警；
- ✅ 直接挂在 `<el-popconfirm>` 上：`el-popconfirm` 渲染后的根节点就是那段触发器，指令拿到根 DOM 一并 `el.remove()`，确认框和它的按钮一起消失，干净无残留。

所以对照表里所有「删除」都**挂在 `el-popconfirm` 上**，不要挂在内层按钮。

#### 坑 2：Pinia 未激活

只在 `mounted` 里 `useUserStore()`（原理见 13.3）。**切忌**在指令**模块顶层**提前调用，否则 pinia 尚未 `app.use()`，会抛 `no active Pinia`。

#### 坑 3：引号漏写

必须 `v-auth="'btn.xxx'"`（写法见 13.4）。漏内层引号 = 取变量 = 值 `undefined` = `buttons.includes(undefined)` 永远 `false` = **所有按钮被移除**。

## 阶段 14：切页动画 transition {#s14}

### 14.1 原理 {#s14-1}

`<router-view>` 默认把匹配到的组件直接渲染。要给它加「进出场动画」，得用 `v-slot` 把内部组件「接出来」，再包进 `<transition>`：

```vue
<router-view v-slot="{ Component }">
  <transition name="fade" mode="out-in">
    <component :is="Component" />
  </transition>
</router-view>
```

- `v-slot="{ Component }"`：`router-view` 把当前路由组件以 scoped slot 形式暴露为 `Component`；
- `<component :is="Component" />`：动态组件渲染它；
- `<transition name="fade">`：Vue 的内置过渡组件，`name` 决定生成的 CSS class 名（`fade-enter-from` 等）；
- `mode="out-in"`：**先让旧页面离场，再让新页面进场**，避免新旧页面叠在一起闪烁（路由切换最常用此模式）。

### 14.2 改造 `src/layout/main/index.vue` {#s14-2}

当前 `main/index.vue` 只有一行 `<router-view></router-view>`（见 `src/layout/main/index.vue`）。替换成带 `v-slot + transition` 的写法：

```vue
<template>
  <router-view v-slot="{ Component }">
    <transition name="fade" mode="out-in">
      <component :is="Component" />
    </transition>
  </router-view>
</template>
```

> **单根节点约束**：`<transition>` 要求**唯一子节点**。本项目各业务页面根节点都是单个 `<el-card>`（如 `trademark/index.vue` 顶层 `<el-card>`），所以 `<component :is>` 渲染出来是单根，过渡正常工作。若某页面用了多个根节点（`<template>` 多根片段），`<transition>` 会告警——届时给该页面最外层包一个 `<div>` 即可（当前页面均无此问题）。

### 14.3 动画样式追加到 `src/style.css` {#s14-3}

`src/style.css` 当前只有基础 reset。在文件末尾追加 `.fade-*` 过渡类：

```css
/* —— 切页动画：淡入 + 轻微缩放（阶段 14） —— */
.fade-enter-from,
.fade-leave-to {
  opacity: 0;
  transform: scale(0.98);
}
.fade-enter-active,
.fade-leave-active {
  transition:
    opacity 0.3s ease,
    transform 0.3s ease;
}
```

> class 名规则：`<transition name="fade">` 会自动拼接出 `fade-enter-from` / `fade-enter-active` / `fade-leave-to` / `fade-leave-active` 四个钩子。改 `name` 时记得同步改 CSS 前缀。

### 14.4 注意项 {#s14-4}

- **只动 `main/index.vue` 的 router-view**：`App.vue` 里的 `<router-view>`（登录页等顶层路由）不需要包过渡，保持原样即可，避免登录/首页也跟着缩放；
- **`mode="out-in"` 与 `<keep-alive>` 可共存**：若以后给 `router-view` 加 `<keep-alive>`，写法是 `<router-view v-slot="{ Component }"><transition name="fade" mode="out-in"><keep-alive><component :is="Component" /></keep-alive></transition></router-view>`，本阶段先不加 keep-alive；
- **动画时长别太长**：`0.3s` 体验最佳，超过 `0.5s` 会显得拖沓；`transform: scale` 幅度控制在 `0.98~0.95`，太大会晕。

## 学习要点总结 {#slearn}

| 要点                                | 关键代码                                 | 说明                                                                                      |
| ----------------------------------- | ---------------------------------------- | ----------------------------------------------------------------------------------------- |
| **自定义指令收敛权限判断**          | `src/directives/auth.ts` 的 `mounted`    | 把「该不该显示」逻辑从每个按钮的 `v-if` 抽到一处，模板只剩 `v-auth="xxx"`，零样板、可复用 |
| **物理移除 vs 隐藏**                | `el.remove()`                            | 比 `v-show` 安全：彻底删除 DOM，DevTools 也看不到，杜绝权限绕过                           |
| **指令内读 Pinia 的时机**           | 在 `mounted` 里 `useUserStore()`         | `mounted` 发生在 `app.use(pinia)` 之后，pinia 已就绪；切忌在模块顶层调用                  |
| **v-auth 必须双层引号**             | `v-auth="'btn.Trademark.add'"`           | 外层 Vue 绑定、内层字符串字面量；漏内层引号 = 取值变量 = `undefined` = 全部移除           |
| **popconfirm 删除按钮挂外层**       | `v-auth` 放 `<el-popconfirm>`            | 根 DOM 一并移除，避免只删按钮留下无触发源的确认框                                         |
| **全局注册位置灵活**                | `app.directive('auth', auth)`            | 只要在 `mount('#app')` 前注册即可，不受 pinia 注册顺序影响                                |
| **transition 需要 v-slot 接出组件** | `router-view v-slot="{ Component }"`     | 直接 `<router-view>` 无法加过渡；先 slot 接出，再 `<component :is>` 渲染                  |
| **mode="out-in" 防重叠**            | `<transition name="fade" mode="out-in">` | 旧页先离场、新页再进场，路由切换最稳，不闪                                                |
| **过渡 class 名随 name**            | `.fade-enter-from` 等                    | `name="fade"` 决定 CSS 前缀，改名要同步改样式                                             |
| **单根节点约束**                    | 页面顶层 `<el-card>`                     | `<transition>` 只认一个子节点；多根页面需包一层 `<div>`                                   |

## 常见报错排查 {#serr}

| 现象                              | 原因                                           | 解决                                                                 |
| --------------------------------- | ---------------------------------------------- | -------------------------------------------------------------------- |
| 所有按钮都不见了                  | `v-auth` 漏写内层引号，值变 `undefined`        | 改成 `v-auth="'btn.xxx'"`（双层引号）                                |
| 控制台报 `no active Pinia`        | 指令里在模块顶层就 `useUserStore()`            | 把调用移到 `mounted(el, binding)` 内部                               |
| 删除按钮点不动 / 控制台告警气泡框 | `v-auth` 挂在内层 `<el-button>` 上，只删了按钮 | 把 `v-auth` 移到外层 `<el-popconfirm>`                               |
| 切页时新页旧页重叠闪烁            | 没加 `mode="out-in"`                           | `<transition>` 加上 `mode="out-in"`                                  |
| 切页毫无动画                      | CSS class 前缀与 `name` 不一致                 | `name="fade"` 必须配 `.fade-enter-from`，改名要同步                  |
| 某页切页时报 transition 单根警告  | 该页面多根节点（片段）                         | 给该页面最外层套一个 `<div>` 或 `<el-card>`                          |
| 权限标识对不上（该隐藏的没隐藏）  | 后端 `buttons` 命名与对照表不符                | `console.log(userStore.userInfo.buttons)` 看真实值，改模板指令值即可 |
