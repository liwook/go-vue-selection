## 0. 后端契约与前提 {#s0}

按钮权限的数据链路是：

```text
登录 → 路由守卫触发 getUserInfo() → buttons = res.data.buttons
                                              │
                                              ▼
                          v-auth 指令在 mounted 时读取该数组做判断
```

**数据结构（以 `apps/server/api/swagger.json` 为准）**

`/api/v1/acl/user/info` 接口（swagger 中 `ResponseUserInfo`）返回 `buttons` 字段，类型为 `string[]`，即按钮权限标识数组；前端 `src/api/schema.d.ts` 的 `ResponseUserInfo` 与之对应，`store/modules/user.ts` 的 `getUserInfo()` 把它写进 `useUserStore().buttons`（store 顶层 ref，非 `userInfo` 对象）。

> ⚠️ swagger 只声明 `buttons` 是「字符串数组」，**不列出具体标识值、也不描述账号差异**。`btn.Trademark.add`、`btn.Sku.updown` 这类命名（`btn.<模块>.<动作>`），以及 `admin` 返回全部标识、非 admin 按角色过滤，都是**后端约定 / 运行时行为**，**以 `console.log(userStore.buttons)` 实际打印为准**。13.5 对照表按尚硅谷标准命名列出，若命名有出入，改指令值即可，结构不动。

## 阶段 13：按钮级权限 v-auth {#s13}

### 13.1 原理：Vue 自定义指令 + Pinia 取 buttons {#s13-1}

Vue 3 自定义指令有 `mounted / updated / unmounted` 等钩子。按钮级权限只需在元素「挂载到 DOM」那一刻判断一次：

1. 指令挂载（`mounted`）时，调用 `useUserStore()` 拿到 pinia 中的 `buttons`；
2. 用 `binding.value`（模板里 `v-auth="'btn.Trademark.add'"` 的单引号字符串）作为「所需权限」；
3. 若 `buttons` 不含该值 → `el.remove()` 直接从 DOM 删掉这个按钮，效果等同于「该按钮不存在」。

为什么用 `mounted + el.remove()` 而不是 `v-if`/`v-show`？

- `v-if` 要在模板里写 `v-if="userStore.buttons.includes('...')"`，每个按钮都要重复取 store、引入 `useUserStore`，模板又臭又长；
- 自定义指令把判断逻辑收敛到一处（`auth.ts`），模板只留一个 `v-auth="xxx"`，语义清晰、可复用、零样板；
- `el.remove()` 是**物理移除**（不是 `display:none`），彻底杜绝「按钮在 DOM 里只是藏起来、用户仍能用 DevTools 改回来看见」的权限绕过隐患。
- 注意：指令只在 `mounted` 判断一次，`v-auth` **不会**随账号切换（登录/登出）实时重算。本项目切账号会走路由刷新或重新登录、组件重新挂载，故无此问题；若后续做「免刷新切换角色」，需改用 `updated` 钩子或 `v-if` 方案。

### 13.2 指令实现 `src/directives/auth.ts`【新增】 {#s13-2}

```ts
// src/directives/auth.ts
import type { Directive, DirectiveBinding } from 'vue'
import { useUserStore } from '@/store/modules/user'

// 自定义指令 v-auth：按钮级权限控制
// 用法：<el-button v-auth="'btn.Trademark.add'">添加品牌</el-button>
// 原理：元素挂载后从 pinia 读取 buttons，
//       若不含指令值则直接 el.remove() 移除该 DOM（不渲染 = 无权限）
const auth: Directive<HTMLElement, string> = {
  mounted(el: HTMLElement, binding: DirectiveBinding<string>) {
    const userStore = useUserStore()
    // 保守策略：buttons 为空（未登录 / 信息未加载）时按「无权限」处理
    const buttons: string[] = userStore.buttons ?? []
    const required = binding.value
    if (!buttons.includes(required)) {
      el.remove()
    }
  },
}

// 说明：项目路由守卫（router/index.ts 的 beforeEach）会先 await getUserInfo()
// 把 buttons 写入 store，再 next() 放行渲染；因此组件 mounted 时 buttons 必然已就绪，
// 不会出现「信息未加载导致按钮被误删」的情况。上面的 ?? [] 仅作兜底防御。

export default auth
```

> 泛型 `Directive<HTMLElement, string>`：第一个参数是被绑定元素的类型，第二个参数是 `binding.value` 的类型（这里是权限字符串）。这样模板里 `v-auth="xxx"` 传非字符串会被 TS 拦下。

### 13.3 全局注册 `src/main.ts` {#s13-3}

在 `app.mount('#app')` 之前，加一行 `app.directive('auth', auth)` 注册。指令名 `auth` 决定模板里写 `v-auth`。

```ts
// src/main.ts（其余 import / createApp / app.use(...) 保持原样）
import { createApp } from 'vue'
import { createPinia } from 'pinia'
import auth from '@/directives/auth' // ← 新增：引入指令

const app = createApp(App)
app.use(createPinia()) // 注册 pinia（指令内部 useUserStore() 依赖它）
app.directive('auth', auth) // ← 新增：全局注册 v-auth
app.mount('#app')
```

> **Pinia 时机保证**：指令只在 `mounted` 钩子里调用 `useUserStore()`，而 `mounted` 发生在组件被插入 DOM 时——此时 `app.use(createPinia())` 早已执行，pinia 已就绪。所以即便把 `app.directive(...)` 写在任何位置（只要在 `mount('#app')` 之前），指令内部读 store 都不会报「getActivePinia was called with no active Pinia」。

### 13.4 模板用法 `v-auth="'btn.xxx'"` {#s13-4}

注意**必须写两对引号**：外层是 Vue 绑定（`v-auth="..."`），内层是 JS 字符串字面量，所以值是 `'btn.Trademark.add'`（单引号串）。漏掉内层引号会变成「取名为 `btn.Trademark.add` 的变量」，运行时 `undefined` → 按钮全被移除。

```vue
<!-- 图标用 @element-plus/icons-vue 按需 import（Plus/Edit/Delete），模板用 :icon 绑定 -->
<!-- 普通按钮：直接挂 -->
<el-button type="primary" v-auth="'btn.Trademark.add'" :icon="Plus" @click="openAdd">
  添加品牌
</el-button>

<!-- 删除按钮被 el-popconfirm 包着，v-auth 挂法见 13.6 -->
<el-popconfirm
  v-auth="'btn.Trademark.remove'"
  :title="`确定删除 ${row.tmName} ?`"
  @confirm="remove(row)"
>
  <template #reference>
    <el-button size="small" type="danger" :icon="Delete">删除</el-button>
  </template>
</el-popconfirm>
```

### 13.6 避坑：`el-popconfirm` 套指令 / Pinia 时机 {#s13-6}

#### 坑 1：删除按钮的 `v-auth` 挂在哪？

删除按钮被 `el-popconfirm` 的 `#reference` 插槽包着。有两种挂法：

- ❌ 挂在内层 `<el-button>` 上：`el.remove()` 只删掉按钮，外层 `el-popconfirm` 失去触发源，会留下一个「没有扳机的气泡确认框」，控制台可能告警；
- ✅ 直接挂在 `<el-popconfirm>` 上：`el-popconfirm` 渲染时把 `reference` 插槽内容作为自己的根节点，指令对根节点调用 `el.remove()` 后，确认框与触发按钮一并从 DOM 消失，干净无残留。

所以对照表里所有「删除」都**挂在 `el-popconfirm` 上**，不要挂在内层按钮。

#### 坑 2：Pinia 未激活

只在 `mounted` 里 `useUserStore()`（原理见 13.3）。**切忌**在指令**模块顶层**提前调用，否则 pinia 尚未 `app.use()`，会抛 `no active Pinia`。

#### 坑 3：引号漏写

必须 `v-auth="'btn.xxx'"`（写法见 13.4）。漏内层引号 = 取变量 = 值 `undefined` = `buttons.includes(undefined)` 永远 `false` = **所有按钮被移除**。

## 阶段 14：切页动画 transition {#s14}

### 14.1 原理 {#s14-1}

`<router-view>` 默认直接渲染匹配组件。加「进出场动画」需用 `v-slot` 把组件「接出来」再包 `<transition>`：

```vue
<router-view v-slot="{ Component }">
  <transition name="fade" mode="out-in">
    <component :is="Component" />
  </transition>
</router-view>
```

- `v-slot="{ Component }"`：把当前路由组件以 scoped slot 暴露为 `Component`；
- `<component :is="Component" />`：动态组件渲染它；
- `<transition name="fade">`：内置过渡组件，`name` 决定 CSS class 前缀（`fade-enter-from` 等）；
- `mode="out-in"`：**先离场再进场**，避免新旧页重叠闪烁（路由切换最常用）。

**本项目为什么要多包一层 `<Suspense>`**：`<Suspense>` **不是 Vue 的通用标配**——静态路由项目（路由写死、所有用户同一套界面）只用上面那段基础写法就够，根本不需要它。它需要出现，是因为本项目的三个特性叠加：

1. 路由是**动态的**：登录后按后端返回的 `menuRoutes` 用 `addRoute` 挂载（见 `router/index.ts`）；
2. 路由组件全是 `() => import(...)` **异步**加载；
3. 加了切页动画 `<transition mode="out-in">`。

首次进入动态路由时，`addRoute` 后必须 `return { ...to, replace: true }` 做**二次导航**（动态路由机制，必须保留），这与 `<transition>` 的「先出后入」状态机在「首次挂载」那一刻竞态：旧页离场被打断、新页 `opacity:0` 残留 → 组件在 DOM 但全白、接口也没发（`onMounted` 没跑）。`<Suspense>` 的作用就是**等异步组件真正解析完成，再让它进入 `<transition>`**，把那个竞态窗口挡在壳里。

**什么场景需要 Suspense（对照）：**

| 场景 | 要不要 Suspense |
| --- | --- |
| 静态路由（写死，所有用户同界面） | 不需要 |
| 动态路由 + 无切页动画 | 不需要 |
| 动态路由 + 切页动画（本项目） | **需要** |

> 💡 **一句话**：动态路由是前提、切页动画是导火索、`<Suspense>` 是灭火器——三者去掉任意一个（尤其动画）都不会白屏。另样式必须去 `scoped`、动画只用 CSS `transition`（见 14.3），否则同样会白屏。

### 14.2 改造 `src/layout/main/index.vue` {#s14-2}

`main/index.vue` 原只有一行 `<router-view></router-view>`。替换为（`v-slot + transition + Suspense`）：

```vue
<template>
  <router-view v-slot="{ Component, route }">
    <transition name="fade" mode="out-in">
      <Suspense>
        <component :is="Component" :key="route.path" />
      </Suspense>
    </transition>
  </router-view>
</template>
```

- **`:key="route.path"`**：带参路由复用同组件（如 `article/:id`）或动态路由二次导航时，强制重新触发进出场动画；缺它会被 Vue 复用旧实例、动画不重播。
- **`<Suspense>`**：给 `<transition>` 一个稳定根节点，内部异步组件加载完才替换内容；没有它，chunk 还在加载状态机就已启动 → 竞态白屏。
- **单根约束**：`<transition>` 要求唯一子节点。本业务页根均为单元素（如 `trademark` 的 `<el-card>`、`spu` 的 `<div class="spu">`）。**特例**：`home/index.vue` 顶层曾是两个 `<el-card>` 多根，需包一层 `<div class="home-wrapper">`。

### 14.3 动画样式写在 `main/index.vue` 的 `<style>`（**非 scoped**） {#s14-3}

本项目无独立全局 `style.css`，过渡样式直接写在 `main/index.vue` 的 `<style>`（去 `scoped`）：

```vue
<style>
/* 必须【非 scoped】！scoped 会编译出 .fade-enter-from[data-v-xxx]，
   而 transition 把 class 加到子组件根上，子组件根无此 data-v → 匹配不到 →
   动画失效/白屏。另：只用 CSS transition（非 animation/@keyframes），
   被打断会自动回自身样式，不残留 opacity:0。 */
.fade-enter-active,
.fade-leave-active {
  transition: opacity 0.3s ease, transform 0.3s ease;
}
.fade-enter-from,
.fade-leave-to {
  opacity: 0;
  transform: scale(0.98);
}
</style>
```

> ⚠️ **为什么去 `scoped`**：`scoped` 给选择器加 `[data-v-xxx]`，但 `fade-*` class 加在 `<component :is>` 渲染出的子组件（如 `AclUser`）根元素上，该根**没有** `main/index.vue` 的 `data-v` → 选择器永远匹配不到 → 动画不生效。去 `scoped` 变全局 `.fade-enter-from` 即可命中任意组件根。
>
> 时长 `0.3s`、缩放 `0.98`（别超 `0.5s`/幅度别太大，否则拖沓发晕）。`<transition name="fade">` 自动拼 `fade-enter-from/active`、`fade-leave-to/active` 四钩子，改 `name` 记得同步改 CSS 前缀。

### 14.4 注意项 {#s14-4}

- **只动 `main/index.vue` 的 router-view**：`App.vue` 的 `<router-view>`（登录页等顶层路由）保持原样，避免登录/首页也跟着缩放；
- **`mode="out-in"` 与 `<keep-alive>` 可共存**：以后要缓存可写 `<router-view v-slot="{ Component }"><transition name="fade" mode="out-in"><keep-alive><component :is="Component" /></keep-alive></transition></router-view>`，本阶段先不加；
- **防白屏三件套（缺一不可）**：① `<component :is>` 包 `<Suspense>`；② 加 `:key="route.path"`；③ 样式写 `<style>`（**非 scoped**）且只用 CSS `transition`。最初遗漏时首次进动态路由会白屏：组件在 DOM 但 `opacity:0`、接口没发（`onMounted` 未执行）；
- **页面遵守单根约束**：`home` 等多根页面需包 `<div class="home-wrapper">`，否则 `<transition>` 告警。

## 学习要点总结 {#slearn}

| 要点                                | 关键代码                                 | 说明                                                                                      |
| ----------------------------------- | ---------------------------------------- | ----------------------------------------------------------------------------------------- |
| **自定义指令收敛权限判断**          | `src/directives/auth.ts` 的 `mounted`    | 把「该不该显示」逻辑从每个按钮的 `v-if` 抽到一处，模板只剩 `v-auth="xxx"`，零样板、可复用 |
| **物理移除 vs 隐藏**                | `el.remove()`                            | 比 `v-show` 安全：彻底删除 DOM，DevTools 也看不到，杜绝权限绕过                           |
| **指令内读 Pinia 的时机**           | 在 `mounted` 里 `useUserStore()`         | `mounted` 发生在 `app.use(pinia)` 之后，pinia 已就绪；切忌在模块顶层调用                  |
| **v-auth 必须双层引号**             | `v-auth="'btn.Trademark.add'"`           | 外层 Vue 绑定、内层字符串字面量；漏内层引号 = 取值变量 = `undefined` = 全部移除           |
| **popconfirm 删除按钮挂外层**       | `v-auth` 放 `<el-popconfirm>`            | 根 DOM 一并移除，避免只删按钮留下无触发源的确认框                                         |
| **全局注册位置灵活**                | `app.directive('auth', auth)`            | 只要在 `mount('#app')` 前注册即可，不受 pinia 注册顺序影响                                |
| **transition 需要 v-slot 接出组件** | `router-view v-slot="{ Component }"`     | 直接 `<router-view>` 无法加过渡；先 slot 接出，再 `<component :is>` 渲染                  |
| **mode="out-in" 防重叠**            | `<transition name="fade" mode="out-in">` | 旧页先离场、新页再进场，路由切换最稳，不闪                                                |
| **过渡 class 名随 name**            | `.fade-enter-from` 等                    | `name="fade"` 决定 CSS 前缀，改名要同步改样式                                             |
| **单根节点约束**                    | 页面顶层 `<el-card>`                     | `<transition>` 只认一个子节点；多根页面需包一层 `<div>`                                   |

## 常见报错排查 {#serr}

| 现象                              | 原因                                           | 解决                                                                 |
| --------------------------------- | ---------------------------------------------- | -------------------------------------------------------------------- |
| 所有按钮都不见了                  | `v-auth` 漏写内层引号，值变 `undefined`        | 改成 `v-auth="'btn.xxx'"`（双层引号）                                |
| 控制台报 `no active Pinia`        | 指令里在模块顶层就 `useUserStore()`            | 把调用移到 `mounted(el, binding)` 内部                               |
| 删除按钮点不动 / 控制台告警气泡框 | `v-auth` 挂在内层 `<el-button>` 上，只删了按钮 | 把 `v-auth` 移到外层 `<el-popconfirm>`                               |
| 切页时新页旧页重叠闪烁            | 没加 `mode="out-in"`                           | `<transition>` 加上 `mode="out-in"`                                  |
| 切页毫无动画                      | CSS class 前缀与 `name` 不一致                 | `name="fade"` 必须配 `.fade-enter-from`，改名要同步                  |
| 某页切页时报 transition 单根警告  | 该页面多根节点（片段）                         | 给该页面最外层套一个 `<div>` 或 `<el-card>`                          |
| 首次进动态路由**整页空白**（连 `el-card` 都没有、网络面板无对应接口请求） | `<component :is>` 没包 `<Suspense>`、或动画写在 `<style scoped>`、或没加 `:key`；异步 `addRoute` 二次导航与 transition 状态机竞态，残留 `opacity:0` | ① `<component>` 外包 `<Suspense>`；② 样式改 `<style>`（去 scoped）；③ 加 `:key="route.path"`；④ 只用 CSS `transition` 不用 `animation` |
| 切页动画不重播（同组件带参路由复用） | 缺 `:key` 导致 Vue 复用旧实例                 | `<component :is="Component" :key="route.path" />`                   |
| 权限标识对不上（该隐藏的没隐藏）  | 后端 `buttons` 命名与对照表不符                | `console.log(userStore.buttons)` 看真实值，改模板指令值即可 |
