## 0. 后端契约总览 {#s0}

> 📌 **请求范式（必读）**：本项目一切请求走 `src/api/client.ts`（`openapi-fetch` 封装），类型来自 `src/api/schema.d.ts`（由 swagger 自动生成，`npm run api:gen` 可刷新）。
>
> ```ts
> import { client } from '@/api'
> // client 已通过 client.use(...) 注册拦截器：
> //   - HTTP 失败（4xx/5xx）或业务 code !== 200 → ElMessage.error + throw
> //   - 自动注入 Authorization: Bearer <token>
> // 因此【不存在】手写 reqXxx 薄封装，也不存在 { data, error } 元组判错分支。
> ```
>
> - 调用：`const { data } = await client.GET('/api/v1/acl/user', { params: { query: {...} } })`，**直接解构 `data`**（错误已在拦截器 throw，走 `try/catch`，无需判断 `error`）；
> - 业务字段在 `data.data`（包裹结构 `result.ResponseData`，见 [0.1](#01-响应结构来自-schemadts)；**成功响应里 `code`/`data`/`message` 三者必有**，直接 `data.data` 取数即可，无需 `?.`）；`data` 为成功响应体，可放心取 `data.data.records` 等；
> - **错误处理**：`client.ts` 中间件已统一——HTTP 失败或业务 `code !== 200` 时 `ElMessage.error` 并 **throw**。因此页面里直接 `try/catch`，**不要再判 `data.code`、也不要判 `error`**；
> - **token**：中间件从 `localStorage`（key `token`）读取并塞 `Authorization: Bearer <token>`，接口层无需关心；
> - **`ElMessage` 需显式 import**：`import { ElMessage } from 'element-plus'` + `import 'element-plus/es/components/message/style/css'`（本项目未配自动导入，自动导入会丢样式）；
> - **登录 / 用户信息 / 退出**在 `src/store/modules/user.ts`（`useUserStore().userInfo` / `getUserInfo()` / `userLogout()`），**没有** `api/user` 模块。

### 0.1 响应结构（来自 `schema.d.ts`）

```ts
// components['schemas']['result.ResponseData'] —— schema.d.ts 里自动生成的真实定义
// 因后端已在 response.go 给字段加 `binding:"required"`（仅供 swag 生成 required，不用于运行时校验），
// openapi-typescript 生成时已去掉 `?`，三字段均为必选。
type ResponseData = {
  code: components['schemas']['result.ResCode'] // 运行时必为 200（成功分支）
  data: unknown     // 运行时必有（成功分支）；删除类等接口为 null，故取数仍需兜底
  message: string   // 运行时必有
}
```

> **成功响应中 `code` / `data` / `message` 三者必有**：`client.ts` 拦截器已保证 HTTP 失败或 `code !== 200` 时直接 `throw`，**能走到业务成功分支的，三字段一定都在**。所以页面取数直接写 `data.data`（无需 `?.`、也无需 `data!.data`）。后端已在 `result.ResponseData` 本体用 `binding:"required"` 标为必选，`schema.d.ts` 中 `code`/`data`/`message` 已无 `?`。各接口的 `data` 具体类型由 `result.ResponseData & { data?: T }` 推导（接口级 `data` 仍可能可选，如菜单树 `data?: types.Menu[]`），需注意区分「本体必选」与「接口级 data 可选」。
> **各模块完整接口契约（path / 参数 / 返回类型）已经全部由 `src/api/schema.d.ts` 自动生成**，调用 `client.GET/POST/...` 时 IDE 会按路径自动补全入参、出参，写错字段名会编译报错，无需手写任何 `reqXxx` 薄封装或类型别名。下面只点名两个最易踩的坑：
>
> - **用户 `PUT /api/v1/acl/user` 的 `id` 在 body，不是 path**（见 [6.1](#s6-1) 直接调 `client.PUT` 的写法）。
> - **`POST /api/v1/acl/permission/role/{roleId}` 的 `permissionId` 是 query 参数，不是 body**（见 [8.1](#s8-1) ⚠️）。

## 1. 代码范式与类型来源 {#s1}

> 所有类型都来自 `src/api/schema.d.ts`（OpenAPI 自动生成的 `components['schemas']`），调用签名来自 `paths`。常用类型速查：
>
> | 用途 | 类型写法 |
> | --- | --- |
> | 用户记录 | `components['schemas']['types.User']` |
> | 用户分页 | `components['schemas']['types.ResponseUserList']` |
> | 角色记录 | `components['schemas']['types.Role']` |
> | 角色分页 | `components['schemas']['types.ResponseRoleList']` |
> | 菜单树节点 | `components['schemas']['types.Menu']` |
> | 分配角色回包 | `components['schemas']['types.ResponseToAssignRole']` |
> | 用户信息 | `components['schemas']['types.ResponseUserInfo']` |
>
> 接口入参/出参也可直接由 `paths['/api/v1/acl/user']['get']['parameters']` 等推导，页面里用 `client` 调用时 IDE 会自动补全类型，无需手写。

### 1.1 接口层怎么写（直接调生成的 `client`） {#s1-1}

本项目**不需要**手写 `src/api/acl/*.ts` 这类薄封装，也**不需要**手写 `reqXxx` 函数或 `type User = ...` 类型别名——`@/api` 直接导出 `openapi-fetch` 的 `client`，所有路径、入参、出参类型都已由 `schema.d.ts` 推导，调用即带类型。页面/store/composable 里这样写：

```ts
import { client } from '@/api'
import type { components } from '@/api/schema'

type User = components['schemas']['types.User']

// 列表：直接调生成的 client，data 一定是成功数据（失败已在拦截器 throw）
const { data } = await client.GET('/api/v1/acl/user', {
  params: { query: { page: 1, limit: 5, username } },
})
const list = data.data.records as User[]   // 类型由 schema.d.ts 校验，写错字段名会编译报错

// 新增/编辑：用 try/catch 感知失败，不要判 error / 不要判 data.code
try {
  await client.POST('/api/v1/acl/user', { body: { username, name, password } })
  ElMessage.success('保存成功')
} catch {
  /* 拦截器已 ElMessage.error，这里只做兜底 */
}
```

> 不要自己再包一层 `reqGetUserList` 之类的函数去返回 `{ data, error }`——`client` 本身已经是对 `openapi-fetch` 的最终封装，再包一层既多余又会把"拦截器失败即 throw"的约定藏起来，反而容易误导调用方去判 `error`。

### 1.2 通用 CRUD 封装 `useCrudTable`（推荐范式） {#s1-2}

三个 ACL 模块（user / role / permission）的列表页结构几乎一致：**分页查询 + 搜索/重置 + 新增/编辑弹窗 + 删除**。为避免每页重写一遍，建议抽一个 `useCrudTable` composable。下面是一份**可直接落地的可用示例**（阶段 9 统一抽取进 `src/composables/useCrudTable.ts`，本章三模块均基于此调用）。

> 封装只负责分页/搜索/弹窗状态，**不负责发请求**——三个 API 函数由调用方传入（内部即"直接调 `client`"的函数，见 [1.1](#s1-1)）。这样封装保持通用、不耦合具体接口路径。

```ts
// src/composables/useCrudTable.ts
import { ref, reactive } from 'vue'
import { ElMessage } from 'element-plus'
import 'element-plus/es/components/message/style/css'

/**
 * 通用分页 CRUD 表格
 * @param listApi   (page, limit, keyword) => Promise<{ data?: {...} }>，内部直接调 client.GET，业务列表在 data.data.records / data.data.total
 * @param saveApi   (payload) => Promise，新增或编辑提交（由 isEdit 决定）
 * @param removeApi (id) => Promise，单条删除
 * @param options.key 用于搜索的关键字字段名（默认 'username'）
 */
export function useCrudTable<T extends { id: number }>(
  listApi: (page: number, limit: number, keyword: string) => Promise<{ data?: { data?: { records?: T[]; total?: number } } }>,
  saveApi: (payload: Partial<T> & { id?: number }) => Promise<unknown>,
  removeApi: (id: number) => Promise<unknown>,
  options: { key?: string } = {},
) {
  const key = options.key ?? 'username'

  const list = ref<T[]>([])
  const total = ref(0)
  const pageNo = ref(1)
  const pageSize = ref(5)
  const keyword = ref('')
  const loading = ref(false)

  const dialogVisible = ref(false)
  const title = ref('新增')
  const form = reactive<Partial<T> & { id?: number }>({})

  async function fetchList() {
    loading.value = true
    try {
      // listApi 内部直接调 client.GET，成功后 data 一定有值；失败已 throw 到 catch
      const { data } = await listApi(pageNo.value, pageSize.value, keyword.value)
      list.value = data.data.records ?? []
      total.value = data.data.total ?? 0
    } finally {
      loading.value = false
    }
  }

  function search() {
    pageNo.value = 1
    fetchList()
  }
  function reset() {
    keyword.value = ''
    pageNo.value = 1
    fetchList()
  }
  function openAdd(blank: Partial<T> & { id?: number }) {
    title.value = '新增'
    Object.assign(form, blank)
    dialogVisible.value = true
  }
  function openEdit(row: T) {
    title.value = '编辑'
    Object.assign(form, row)
    dialogVisible.value = true
  }
  async function save() {
    try {
      await saveApi(form)
      ElMessage.success('操作成功')
      dialogVisible.value = false
      fetchList()
    } catch {
      /* 中间件已 ElMessage.error，仅阻止后续流程 */
    }
  }
  async function remove(row: T) {
    try {
      await removeApi(row.id)
      ElMessage.success('删除成功')
      if (list.value.length === 1 && pageNo.value > 1) pageNo.value--
      fetchList()
    } catch {
      /* 中间件已提示错误 */
    }
  }

  return {
    key, list, total, pageNo, pageSize, keyword, loading,
    dialogVisible, title, form,
    fetchList, search, reset, openAdd, openEdit, save, remove,
  }
}
```

> 调用方只需传 3 个 API 函数 + 关键字字段名，`list / loading / pagination / dialogVisible / form / fetchList / search / save / remove` 全部复用，页面 `<script setup>` 从 ~120 行降到 ~30 行，**模板不变**（弹窗、表格、分页照常写，只是状态名改成返回的那几个）。
>
> 非分页场景（如阶段 8 菜单树）不适用本封装，见 [8.2](#s8-2)。

## 阶段 6：用户管理 {#s6}

### 6.1 接口契约（直接调 `client`，无独立接口层文件） {#s6-1}

> 本项目**没有** `src/api/acl/user.ts` 这类接口层文件——所有请求在页面/composable 里直接 `import { client } from '@/api'` 调用，path / 入参 / 出参类型由 `src/api/schema.d.ts` 自动推导（写错即编译报错）。下面列出用户模块用到的路径与调用范式，类型直接取 `components['schemas']`：

```ts
import { client } from '@/api'
import type { components } from '@/api/schema'

type User = components['schemas']['types.User']
type ResponseToAssignRole = components['schemas']['types.ResponseToAssignRole']

// 列表（username 为空则查全部）：GET /api/v1/acl/user
const { data } = await client.GET('/api/v1/acl/user', {
  params: { query: { page, limit, username } },
})
const list = data.data.records as User[]

// 新增：POST /api/v1/acl/user
await client.POST('/api/v1/acl/user', { body: { username, name, password } })

// 修改（id 在 body，不在 path）：PUT /api/v1/acl/user
await client.PUT('/api/v1/acl/user', { body: { id, username, name } })

// 删除：DELETE /api/v1/acl/user/{id}
await client.DELETE(`/api/v1/acl/user/${id}`)

// 获取某用户已分配/全部角色：GET /api/v1/acl/user/{userId}/role
const { data: r } = await client.GET(`/api/v1/acl/user/${userId}/role`)
const assign = r!.data as ResponseToAssignRole

// 给用户分配角色：POST /api/v1/acl/user/{userId}/role
await client.POST(`/api/v1/acl/user/${userId}/role`, { body: { userId, roleIdList } })
```

> 以上每个调用都已有完整类型，**切勿再包一层 `reqXxx` 函数**——`client` 本身就是最终封装，多包一层只会把"失败即 throw"的约定藏起来。失败统一在 `try/catch` 感知（见 [6.2](#s6-2)）。

### 6.2 页面 `src/views/acl/user/index.vue` {#s6-2}

列表/新增/编辑/删除走 [1.2](#s1-2) 的 `useCrudTable`；"分配角色"是用户模块**专属**功能，封装之外单独写。

**① 调用封装（`<script setup>` 顶部）**

```ts
import { onMounted } from 'vue'
import { client } from '@/api'
import { useCrudTable } from '@/composables/useCrudTable'
import type { components } from '@/api/schema'

type User = components['schemas']['types.User']

// 列表 + 新增/编辑/删除 全部托管给封装；
// 三个 API 函数直接调 client（路径/类型由 schema.d.ts 校验）
const {
  list: userList, total, pageNo, pageSize, keyword, loading,
  dialogVisible, title, form: userForm,
  fetchList, search, reset, openAdd, openEdit, save, remove: removeUser,
} = useCrudTable<User>(
  // listApi：直接 client.GET
  (page, limit, username) =>
    client.GET('/api/v1/acl/user', { params: { query: { page, limit, username } } }),
  async (payload) => {   // saveApi：新增/编辑差异在密码是否提交
    if (payload.id) {
      const { password: _pw, ...rest } = payload
      void _pw
      await client.PUT('/api/v1/acl/user', { body: rest as { id: number; username: string; name: string } })
    } else {
      await client.POST('/api/v1/acl/user', { body: payload as { username: string; name: string; password: string } })
    }
  },
  (id) => client.DELETE(`/api/v1/acl/user/${id}`),
  { key: 'username' },
)

onMounted(fetchList)

// 新增时的空白表单：密码在编辑时不强制
function addUser() {
  openAdd({ username: '', name: '', password: '' } as User & { password?: string })
}
```

**② 模板**：搜索栏 / 表格 / 分页 / 新增编辑弹窗与之前一致，状态名换成封装返回的 `userList / pageNo / pageSize / keyword / loading / dialogVisible / title / userForm`，`@click` 绑 `search / reset / openAdd / openEdit / save / removeUser`。新增按钮改绑 `addUser`（空白表单带 `password`）。表格列里"密码"输入框用 `userForm.password`，编辑时留空 = 不改密码（见下方 `saveApi`）。

#### ③ 分配角色（封装外，专属逻辑）

```ts
const assignVisible = ref(false)
const allRoles = ref<ResponseToAssignRole['allRolesList']>([])
const checkedRoles = ref<number[]>([])
const checkAll = ref(false)
const isIndeterminate = ref(false)
let assignUserId = 0

async function openAssign(row: User) {
  assignUserId = row.id
  // 直接调 client.GET，data 已为成功数据（失败 throw 到 catch）
  const { data } = await client.GET(`/api/v1/acl/user/${assignUserId}/role`)
  allRoles.value = data.data.allRolesList ?? []
  checkedRoles.value = (data.data.assignRoles ?? []).map((r) => r.id as number)
  syncCheckAll()
  assignVisible.value = true
}
function syncCheckAll() {
  const n = allRoles.value.length
  checkAll.value = n > 0 && checkedRoles.value.length === n
  isIndeterminate.value = checkedRoles.value.length > 0 && checkedRoles.value.length < n
}
function handleCheckAll(val: boolean) {
  checkedRoles.value = val ? allRoles.value.map((r) => r.id) : []
  isIndeterminate.value = false
}
async function confirmAssign() {
  try {
    await client.POST(`/api/v1/acl/user/${assignUserId}/role`, { body: { userId: assignUserId, roleIdList: checkedRoles.value } })
    ElMessage.success('分配成功')
    assignVisible.value = false
  } catch { /* 中间件已提示 */ }
}
```

> 完整模板与 `el-checkbox` 写法见原"分配角色"弹窗片段：`el-checkbox` 用 `:value` 绑值、默认插槽放文字（EP 2.x）；`ElMessage` 仍需显式 import 样式。

## 阶段 7：角色管理 + 分配权限 {#s7}

### 7.1 接口契约（直接调 `client`，无独立接口层文件） {#s7-1}

> 同 [6.1](#s6-1)，角色模块也不存在 `src/api/acl/role/index.ts`——直接 `import { client } from '@/api'`。路径与调用范式如下，类型来自 `schema.d.ts`：

```ts
import { client } from '@/api'
import type { components } from '@/api/schema'

type Role = components['schemas']['types.Role']

// 列表：GET /api/v1/acl/role
const { data } = await client.GET('/api/v1/acl/role', {
  params: { query: { page, limit, roleName } },
})
const list = data.data.records as Role[]

// 新增：POST /api/v1/acl/role
await client.POST('/api/v1/acl/role', { body: { roleName, remark } })

// 修改：PUT /api/v1/acl/role/{id}（注意 id 在 path）
await client.PUT(`/api/v1/acl/role/${id}`, { body: { id, roleName, remark } })

// 删除：DELETE /api/v1/acl/role/{id}
await client.DELETE(`/api/v1/acl/role/${id}`)
```

> 角色编辑的 `id` 在 **path**（与用户模块"id 在 body"不同），这是 swagger 契约决定的差异，调用时留意。

### 7.2 页面 `src/views/acl/role/index.vue` {#s7-2}

新建 `src/views/acl/role/index.vue`。列表 + 新增/编辑/删除同样走 `useCrudTable`，差异只在 `saveApi` 直接复用接口（无密码分支）、关键字字段为 `roleName`；"分配权限"树是专属逻辑。

#### ① 调用封装

```ts
import { ref, onMounted } from 'vue'
import { client } from '@/api'
import { ElMessage } from 'element-plus'
import 'element-plus/es/components/message/style/css'
import { useCrudTable } from '@/composables/useCrudTable'
import type { components } from '@/api/schema'

type Role = components['schemas']['types.Role']
type Menu = components['schemas']['types.Menu']

const {
  list: roleList, total, pageNo, pageSize, keyword, loading,
  dialogVisible, title, form: roleForm,
  fetchList, search, reset, openAdd, openEdit, save, remove: removeRole,
} = useCrudTable<Role>(
  (page, limit, roleName) =>
    client.GET('/api/v1/acl/role', { params: { query: { page, limit, roleName } } }),
  (payload) =>
    payload.id
      ? client.PUT(`/api/v1/acl/role/${payload.id}`, { body: payload as Role })
      : client.POST('/api/v1/acl/role', { body: payload as Role }),
  (id) => client.DELETE(`/api/v1/acl/role/${id}`),
  { key: 'roleName' },
)

onMounted(fetchList)
```

**② 模板**：与用户页一致，状态名换成 `roleList / pageNo / ... / roleForm`，操作列 `@click` 绑 `openAssign / openEdit / removeRole`。新增/编辑弹窗只含 `roleName` + `remark` 两个表单项。

#### ③ 分配权限（封装外，专属逻辑）

```ts
const assignVisible = ref(false)
const menuTree = ref<Menu[]>([])
const checkedKeys = ref<number[]>([])
const treeRef = ref<InstanceType<typeof ElTree> | null>(null)
let assignRoleId = 0

async function openAssign(row: Role) {
  assignRoleId = row.id
  const { data } = await client.GET(`/api/v1/acl/permission/role/${assignRoleId}`)
  menuTree.value = data.data ?? []
  const ids: number[] = []
  const walk = (nodes: Menu[]) =>
    nodes.forEach((n) => {
      if (n.select) ids.push(n.id)
      if (n.children) walk(n.children)
    })
  walk(menuTree.value)
  checkedKeys.value = ids
  assignVisible.value = true
}
function onTreeOpened() {
  treeRef.value?.setCheckedKeys(checkedKeys.value) // 弹窗展开后再设默认勾选
}
async function confirmAssign() {
  try {
    const checked = treeRef.value?.getCheckedKeys() ?? []
    const half = treeRef.value?.getHalfCheckedKeys() ?? []
    // ⚠️ permissionId 是 query 参数（csv 拼接），不是 body
    await client.POST(`/api/v1/acl/permission/role/${assignRoleId}`, {
      params: { query: { permissionId: [...checked, ...half].join(',') } },
    })
    ElMessage.success('分配成功')
    assignVisible.value = false
  } catch { /* 中间件已提示 */ }
}
```

> **分配权限关键点**：`client.POST('/api/v1/acl/permission/role/{roleId}', { params: { query: { permissionId } } })` 走 **query 参数**（`permissionId` 逗号拼接），调用范式见 [8.1](#s8-1)；`el-tree` 用 `check-strictly` 避免父子联动，确认时合并 `getCheckedKeys()`（全选叶子）+ `getHalfCheckedKeys()`（半选父节点）一起提交，才能完整还原后端的 `select` 集合。模板里 `<el-tree node-key="id" :props="{ label: 'name', children: 'children' }" :default-checked-keys="checkedKeys" check-strictly>`。

## 阶段 8：菜单管理 {#s8}

### 8.1 接口契约（直接调 `client`，无独立接口层文件） {#s8-1}

> 同理，菜单/权限模块不存在 `src/api/acl/permission/index.ts`，直接 `import { client } from '@/api'`。路径与调用范式如下，类型来自 `schema.d.ts`：

```ts
import { client } from '@/api'
import type { components } from '@/api/schema'

type Menu = components['schemas']['types.Menu']

// 菜单权限树：GET /api/v1/acl/permission → Menu[]
const { data: menuData } = await client.GET('/api/v1/acl/permission')
const tree = menuData.data as Menu[]

// 根据角色获取菜单树（含 select 标记）：GET /api/v1/acl/permission/role/{roleId} → Menu[]
const { data: roleMenu } = await client.GET(`/api/v1/acl/permission/role/${roleId}`)
const roleTree = roleMenu!.data as Menu[]

// ⚠️ 给角色分配权限：permissionId 是 query 参数（csv 拼接），不是 body
await client.POST(`/api/v1/acl/permission/role/${roleId}`, {
  params: { query: { permissionId: idList.join(',') } },
})

// 新增菜单：POST /api/v1/acl/permission
await client.POST('/api/v1/acl/permission', { body: menu })

// 修改菜单：PUT /api/v1/acl/permission/{id}
await client.PUT(`/api/v1/acl/permission/${menu.id}`, { body: menu })

// 删除菜单：DELETE /api/v1/acl/permission/{id}
await client.DELETE(`/api/v1/acl/permission/${id}`)
```

> 注意：`client.POST('/api/v1/acl/permission/role/{roleId}', { params: { query: { permissionId } } })` 走 **query 参数**（`permissionId` 逗号拼接），写成 body 会 201；client 对字符串 query 不二次展开，正好成 csv。

### 8.2 页面 `src/views/acl/permission/index.vue` {#s8-2}

菜单是**树形**数据（一次拉全树，无分页），[1.2](#s1-2) 的 `useCrudTable` 不适用，这里直接用 `ref` + 自定义函数。模板用 `el-table` 树形模式（`:tree-props="{ children: 'children' }"`，`row-key="id"`）。

#### ① 脚本（仅差异点）

```ts
import { ref, onMounted } from 'vue'
import { client } from '@/api'
import { ElMessage } from 'element-plus'
import 'element-plus/es/components/message/style/css'
import type { components } from '@/api/schema'

type Menu = components['schemas']['types.Menu']

const menuTree = ref<Menu[]>([])
const loading = ref(false)
const dialogVisible = ref(false)
const title = ref('')
// level/type 必须是 number（契约如此），初始值直接传数字
const menuForm = ref<{ id?: number; name: string; code: string; level: number; pid: number; type: number }>({
  name: '', code: '', level: 1, pid: 0, type: 1,
})

onMounted(getMenu)
async function getMenu() {
  loading.value = true
  try {
    const { data } = await client.GET('/api/v1/acl/permission')
    menuTree.value = data.data ?? []
  } finally {
    loading.value = false
  }
}

function openAdd(parent: Menu | null) {
  const level = parent ? Number(parent.level) + 1 : 1
  title.value = parent ? `添加「${parent.name}」的子项` : '添加一级菜单'
  menuForm.value = { name: '', code: '', level, pid: parent ? parent.id : 0, type: level === 3 ? 3 : level }
  dialogVisible.value = true
}
function openEdit(row: Menu) {
  title.value = '编辑菜单'
  menuForm.value = { id: row.id, name: row.name, code: String(row.code), level: row.level, pid: row.pid, type: row.type }
}
async function save() {
  try {
    const f = menuForm.value
    if (f.id) await client.PUT(`/api/v1/acl/permission/${f.id}`, { body: { id: f.id, name: f.name, level: f.level, pid: f.pid, code: f.code } })
    else await client.POST('/api/v1/acl/permission', { body: { name: f.name, level: f.level, pid: f.pid, type: f.type, code: f.code } })
    ElMessage.success('操作成功')
    dialogVisible.value = false
    getMenu()
  } catch { /* 中间件已提示 */ }
}
async function removeMenu(row: Menu) {
  try {
    await client.DELETE(`/api/v1/acl/permission/${row.id}`)
    ElMessage.success('删除成功')
    getMenu()
  } catch { /* 中间件已提示 */ }
}
```

**② 模板要点**：表格列用 `<el-table-column label="类型" #default="{ row }">` 按 `row.type` 渲染不同 `el-tag`（1=菜单 / 2=菜单 / 3=按钮）；操作列 `row.level < 3` 时才显示"添加子项"按钮；弹窗里"层级"用 `:model-value="menuForm.level"` 禁用展示。

> 删除有子节点的菜单时，后端返回 `code: 208`（节点下有子节点，不可删除），client 中间件弹错误并 throw；如需级联删除需后端额外接口，此处按标准契约保持原样。`code` 后端为字符串、`level/type` 为数字，回显用 `String(row.code)`，提交时 `level/type` 保持数字（见 [学习要点](#slearn)）。

## 学习要点总结 {#slearn}

| 要点                                                            | 关键代码                                                                                       | 说明                                                                                                                                                                                                   |
| --------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **通用 CRUD 抽封装**                                            | `useCrudTable(listApi, saveApi, removeApi, { key })`                                         | user/role 的分页列表 + 增/删/改 全部托管给 [1.2](#s1-2) 封装，页面只传 3 个 API + 关键字字段名；分页、搜索、loading 复位、空 catch 已由封装内部统一处理，页面 `<script>` 量降约 60%                     |
| **`ref`/`reactive` 用泛型定状态形状**                           | `ref<User[]>([])`、`reactive<{ id?: number; ... }>({...})`                                   | 空数组会被推断成 `never[]`，初始对象缺字段（如 `userForm.id`）会"不存在"；显式泛型补全，避免取数/赋值编译期报错                                                       |
| **字段类型严格对齐后端契约**                                    | `menuForm` 的 `level`/`type` 用 `number`                                                     | 契约里 `level`/`type` 是数字（`code` 才是 string）；表单字段也必须是 `number`，否则 `payload` 赋值处报类型错；初始值直接传数字                                                                      |
| **`/permission/role/{roleId}` 的 `permissionId` 是 query 参数** | `params: { query: { permissionId: idList.join(',') } }`                                       | 写成 body 会 201；client 对字符串 query 不二次展开，正好成 csv                                                                                                                                      |
| **`el-tree` 分配权限**                                          | `check-strictly` + `getCheckedKeys()` + `getHalfCheckedKeys()`                               | 父子不联动，确认时合并全选+半选节点                                                                                                                                                                  |
| **`ElMessage` 需显式 import**                                   | `import { ElMessage } from 'element-plus'` + `import 'element-plus/es/components/message/style/css'` | 本项目未配自动导入，漏了样式会丢（阶段 5 结论）                                                                                                                  |
| **编辑用户密码可选**                                            | `saveApi` 编辑分支 `if (payload.password) ...`                                               | 密码留空则不提交 `password` 字段，后端 `update` 只需 `{id,username,name}`，密码留空=不改（见 [6.2](#s6-2) 的 `saveApi`）                                                                             |
| **错误已统一处理，catch 可空**                                  | `catch { /* 中间件已提示错误 */ }`                                                          | 非 200 已在 client 中间件 `ElMessage.error` 并 throw，页面 catch 写空处理即可；`catch {}` 不接变量是 ES2019+ 合法写法。封装内已包好，自定义接口（分配角色/权限）仍照此写                          |
| **分配类接口是子资源，路径各异**                                | 用户页 `client.GET('/api/v1/acl/user/{userId}/role')` / 角色页 `client.GET('/api/v1/acl/permission/role/{roleId}')` | 两者路径不同、返回结构不同，别混淆；都是直接调 `client`，没有 `reqXxx` 封装                                                                                        |
| **时间字段可选、兜底渲染**                                      | `{{ row.createTime \|\| '-' }}`                                                              | `createTime?` 后端字段为空时不返回，缺省显示 `-` 避免 `undefined`；无需 `formatTime` 工具                                                                              |

## 常见报错排查 {#serr}

| 现象                                | 原因                                                                     | 解决                                                                                                                                 |
| ----------------------------------- | ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------ |
| 分配权限提交后无变化 / 控制台报 201 | 把 `permissionId` 写成 JSON body                                         | 改成 query 参数：`client.POST(url, { params: { query: { permissionId: idList.join(',') } } })`                                        |
| 页面取数 `undefined`                | 直接用了返回值当业务数据                                                 | `client` 成功时 `data` 即为响应体，业务字段在 `data.data`（包裹结构 `result.ResponseData`，成功响应三字段必有，直接 `data.data` 取数），取 `data.data.records` 等；不要判 `error`，失败已在拦截器 throw                                       |
| `ElMessage` 弹窗纯白无样式          | 只 `import { ElMessage }` 漏了样式                                       | 补 `import 'element-plus/es/components/message/style/css'`；本项目未配自动导入                                                         |
| 删除菜单报 208「节点下有子节点」    | 该菜单含子节点                                                           | 先删子节点，或后端加级联删除接口                                                                                                     |
| 角色权限勾选后再次打开不全          | 只提交 `getCheckedKeys()` 漏了半选父节点                                 | 合并 `getHalfCheckedKeys()` 一起提交                                                                                                 |
| `el-checkbox` 不显示文字            | 用了旧版 `label` 绑值                                                    | EP 2.x 用 `:value` 绑值、默认插槽放文字                                                                                              |
| 点菜单项高亮变了但路由不跳转        | 递归 `SideMenu` 出现了**嵌套** `<el-menu>`（每层各包一个），内层 el-menu 吞掉 `click` 事件 | 整个侧边栏只保留**一个** `<el-menu>`（根实例包，递归子实例只渲染 `el-menu-item`/`el-sub-menu`，不要再加 el-menu）；点击用 `@click` 手动 `$router.push`；本项目 `SideMenu` 已是单根结构，正常情况下不会触发此问题 |
