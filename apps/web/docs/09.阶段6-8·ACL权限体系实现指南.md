## 0. 后端契约总览 {#s0}

> 📌 **请求范式（必读）**：本项目**没有**手写 axios 实例 / `utils/request.ts` / `api/type.ts`。一切请求走 `src/api/client.ts`（`openapi-fetch` 封装），类型来自 `src/api/schema.d.ts`（由 swagger 自动生成，`npm run api:gen` 可刷新）。
>
> - 调用：`const { data, error } = await client.GET('/api/v1/acl/user', { params: { query: {...} } })`，返回 `{ data, error }` 元组（`error` 在 HTTP 非 2xx 时存在）；
> - 业务字段在 `data.data`（包裹结构 `{ code, data, message, ok }`）；
> - **错误处理**：`client.ts` 中间件已统一——HTTP 失败或业务 `code !== 200` 时 `ElMessage.error` 并 **throw**。因此页面里直接 `try/catch`，**不要再判 `data.code`**；
> - **token**：中间件从 `localStorage`（key `token`）读取并塞 `Authorization: Bearer <token>`，接口层无需关心；
> - **`ElMessage` 需显式 import**：`import { ElMessage } from 'element-plus'` + `import 'element-plus/es/components/message/style/css'`（本项目未配自动导入，自动导入会丢样式）；
> - **登录 / 用户信息 / 退出**在 `src/store/modules/user.ts`（`useUserStore().userInfo` / `getUserInfo()` / `userLogout()`），**没有** `api/user` 模块。

### 0.1 响应结构（来自 `schema.d.ts`）

```ts
// components['schemas']['result.ResponseData']
interface ResponseData {
  code: number // 200 成功；其余业务码见 pkg/result/code.go
  data?: unknown // 业务数据，类型随接口而定
  message: string
  ok: boolean
}
```

### 0.2 各模块接口清单

**用户 `/api/v1/acl/user`**

| 方法   | 路径                  | 入参                                               | 返回 `data`                                                                 | 作用                                                  |
| ------ | --------------------- | -------------------------------------------------- | --------------------------------------------------------------------------- | ----------------------------------------------------- |
| GET    | `/api/v1/acl/user`               | query `page,limit,username?`                       | `types.ResponseUserList { records: types.User[]; total; ... }` | 分页查询用户列表；`username` 为空则查全部             |
| POST   | `/api/v1/acl/user`               | body `{ username, name, password }`（必填）        | `null`                                                                      | 新增用户，三字段必填                                   |
| PUT    | `/api/v1/acl/user`      | body `{ id, username, name }`（**id 在 body，非路径**） | `null`                                                                      | 修改用户                                              |
| DELETE | `/api/v1/acl/user/{userId}`      | path                                               | `null`                                                                      | 删除单个用户                                          |
| GET    | `/api/v1/acl/user/{userId}/role` | path                                               | `types.ResponseToAssignRole { allRolesList: Role[]; assignRoles: Role[] }`        | 打开「分配角色」前拉数据：全部角色 + 该用户已分配角色 |
| POST   | `/api/v1/acl/user/{userId}/role` | body `{ userId: number; roleIdList: number[] }`    | `null`                                                                      | 确认把用户绑定到选中的多个角色                        |
| GET    | `/api/v1/acl/user/info` | — | `types.ResponseUserInfo { avatar; buttons[]; name; roles[]; routes[] }` | 当前登录用户信息（已收纳在 `useUserStore().getUserInfo()`） |

> `ResponseUser` 字段：`id, username, name, password, phone, roleName, createTime?, updateTime?`（`createTime` / `updateTime` 为可选，后端在字段为空时不返回该字段）；`ResponseUserInfo`：`avatar, buttons[], name, roles[], routes[]`。

**角色 `/api/v1/acl/role`**

| 方法   | 路径             | 入参                                        | 返回 `data`                                                         | 作用                                      |
| ------ | ---------------- | ------------------------------------------- | ------------------------------------------------------------------- | ----------------------------------------- |
| GET    | `/role`          | query `page,limit,roleName?`                | `types.ResponseRoleList { records: Role[]; total; ... }` | 分页查询角色列表；`roleName` 为空则查全部 |
| POST   | `/role`          | body `{ roleName, remark? }`                | `null`                                                              | 新增角色，`remark` 备注可选               |
| PUT    | `/role/{roleId}` | body `{ id, roleName, remark? }`（路径 id） | `null`                                                              | 修改角色                                  |
| DELETE | `/role/{roleId}` | path                                        | `null`                                                              | 删除角色                                  |

> `Role` 字段：`id, roleName, remark, createTime?, updateTime?`（`createTime` / `updateTime` 为可选，后端在字段为空时不返回该字段）。

**菜单/权限 `/api/v1/acl/permission`**

| 方法   | 路径                         | 入参                                     | 返回 `data`                                 | 作用                                                  |
| ------ | ---------------------------- | ---------------------------------------- | ------------------------------------------- | ----------------------------------------------------- |
| GET    | `/permission`                | —                                        | `types.Menu[]`（树，`children` 嵌套）             | 拉整棵权限菜单树                                      |
| GET    | `/permission/role/{roleId}`  | path                                     | `types.Menu[]`（树，已分配节点带 `select: true`） | 打开「分配权限」前拉数据，已勾选节点带 `select: true` |
| POST   | `/permission/role/{roleId}`  | **query** `permissionId`(int 数组, csv)  | `null`                                      | 确认把权限树绑定给角色（⚠️ query 参数，非 body）      |
| POST   | `/permission`                | body `{ name, code?, level, pid, type }` | `null`                                      | 新增菜单/按钮权限节点                                 |
| PUT    | `/permission/{permissionId}` | body `{ id, name, code?, level, pid }`   | `null`                                      | 修改某个权限节点                                      |
| DELETE | `/permission/{permissionId}` | path                                     | `null`（有子节点时 `code` 返回业务错误码） | 删除权限节点；有子节点后端拒绝并给错误 `code`                 |

> `Menu` 字段：`id, pid, name, code, level, type, status, toCode, select?, children?`。`type`：1=一级菜单，2=二级菜单，3=按钮功能；`level`：1/2/3 对应层级。`code` 为字符串、`level`/`type` 为数字（新 REST 契约；旧版 `code` 为数字、`level`/`type` 为字符串）。

⚠️ **最易踩的坑：`POST /permission/role/{roleId}` 的 `permissionId` 是 query 参数，不是 body！** 我们把 `permissionId` 拼在 URL 上（`?permissionId=1,7,8,...`）才返回 200，任何写成 JSON body 的尝试都返回 201 参数错误。用 `client` 的写法：

```ts
await client.POST(`/api/v1/acl/permission/role/${roleId}`, {
  params: { query: { permissionId: permissionId.join(',') } },
})
```

（`client` 对字符串 query 不会二次展开，正好形成 `permissionId=1,7,8` 的 csv 形式。）

## 1. 代码范式与类型来源 {#s1}

> **不要**新建 `src/api/type.ts` 或 `src/api/acl/type.ts`。所有类型都来自 `src/api/schema.d.ts`（OpenAPI 自动生成的 `components['schemas']`），调用签名来自 `paths`。常用类型速查：
>
> | 用途 | 类型写法 |
> | --- | --- |
> | 用户记录 | `components['schemas']['types.User']` |
> | 用户分页 | `components['schemas']['types.ResponseUserList']` |
> | 角色记录 | `components['schemas']['types.Role']` |
> | 角色分页 | `components['schemas']['types.ResponseRoleList']` |
> | 菜单树节点 | `components['schemas']['types.Menu']` |
> | 分配角色回包 | `components['schemas']['types.ResponseToAssignRole']` |
> | 用户信息 | `components['schemas']['types.ResponseUserInfo']` |
>
> 接口入参/出参也可直接由 `paths['/api/v1/acl/user']['get']['parameters']` 等推导，页面里用 `client` 调用时 IDE 会自动补全类型，无需手写。

### 1.1 接口层怎么写（薄封装示例）

不手写 axios，统一在 `src/api/acl/*` 里薄封装 `client`：

```ts
// src/api/acl/user.ts
import { client } from '@/api/client'
import type { components } from '@/api/schema'

type User = components['schemas']['types.User']
type ResponseUserList = components['schemas']['types.ResponseUserList']

// GET 分页
export const reqGetUserList = (page: number, limit: number, username = '') =>
  client.GET('/api/v1/acl/user', { params: { query: { page, limit, username } } })

// POST 新增
export const reqAddUser = (data: { username: string; name: string; password: string }) =>
  client.POST('/api/v1/acl/user', { body: data })

// PUT 修改（id 在 body）
export const reqUpdateUser = (data: { id: number; username: string; name: string }) =>
  client.PUT('/api/v1/acl/user', { body: data })

// DELETE 删除
export const reqRemoveUser = (id: number) =>
  client.DELETE(`/api/v1/acl/user/${id}`)
```

> 页面里 `const { data, error } = await reqGetUserList(1, 5)`；`data?.data.records` 即列表。`error` 存在即请求失败（已被中间件弹过提示并 throw，正常走到 catch）。

## 阶段 6：用户管理 {#s6}

### 6.1 接口层 `src/api/acl/user.ts` {#s6-1}

> 类型全部来自 `src/api/schema.d.ts`（见第 1 章），本文件只放薄封装函数，统一 `from '@/api/schema'` 引类型。

```ts
import { client } from '@/api/client'
import type { components } from '@/api/schema'

type User = components['schemas']['types.User']
type ResponseUserList = components['schemas']['types.ResponseUserList']
type ResponseToAssignRole = components['schemas']['types.ResponseToAssignRole']

// 用户分页列表（username 为空则查全部）
export const reqGetUserList = (page: number, limit: number, username = '') =>
  client.GET('/api/v1/acl/user', { params: { query: { page, limit, username } } })

// 新增用户
export const reqAddUser = (data: { username: string; name: string; password: string }) =>
  client.POST('/api/v1/acl/user', { body: data })

// 修改用户（id 在 body）
export const reqUpdateUser = (data: { id: number; username: string; name: string; password?: string }) =>
  client.PUT('/api/v1/acl/user', { body: data })

// 删除用户
export const reqRemoveUser = (id: number) => client.DELETE(`/api/v1/acl/user/${id}`)

// 获取某用户已分配/全部角色：GET /user/{userId}/role
export const reqGetUserRoles = (userId: number) =>
  client.GET(`/api/v1/acl/user/${userId}/role`)

// 给用户分配角色：POST /user/{userId}/role
export const reqAssignUserRoles = (userId: number, roleIdList: number[]) =>
  client.POST(`/api/v1/acl/user/${userId}/role`, { body: { userId, roleIdList } })

export type { User, ResponseUserList, ResponseToAssignRole }
```

### 6.2 页面 `src/views/acl/user/index.vue` {#s6-2}

把占位页 `src/views/acl/user/index.vue` 整体替换为下面内容。

```vue
<template>
  <el-card>
    <!-- 搜索栏 -->
    <el-form :inline="true" class="mb-4">
      <el-form-item label="用户名">
        <el-input v-model="keyword" placeholder="请输入用户名" clearable />
      </el-form-item>
      <el-form-item>
        <el-button type="primary" @click="search">搜索</el-button>
        <el-button @click="reset">重置</el-button>
      </el-form-item>
    </el-form>

    <el-button type="primary" icon="Plus" @click="openAdd">添加用户</el-button>
    <el-button type="danger" :disabled="selectIds.length === 0" @click="batchDelete">
      批量删除
    </el-button>

    <!-- 用户表格 -->
    <el-table
      class="mt-4"
      border
      :data="userList"
      v-loading="loading"
      @selection-change="handleSelection"
    >
      <el-table-column type="selection" width="55" />
      <el-table-column label="ID" prop="id" width="80" />
      <el-table-column label="用户名" prop="username" />
      <el-table-column label="昵称" prop="name" />
      <el-table-column label="角色" prop="roleName" />
      <el-table-column label="创建时间">
        <template #default="{ row }">{{ row.createTime || '-' }}</template>
      </el-table-column>
      <el-table-column label="操作" width="280">
        <template #default="{ row }">
          <el-button size="small" type="info" @click="openAssign(row)"> 分配角色 </el-button>
          <el-button size="small" type="primary" @click="openEdit(row)"> 编辑 </el-button>
          <el-popconfirm :title="`确定删除 ${row.username} ?`" @confirm="removeUser(row)">
            <template #reference>
              <el-button size="small" type="danger">删除</el-button>
            </template>
          </el-popconfirm>
        </template>
      </el-table-column>
    </el-table>

    <!-- 分页 -->
    <el-pagination
      class="mt-4"
      v-model:current-page="pageNo"
      v-model:page-size="pageSize"
      :page-sizes="[5, 10, 20]"
      :total="total"
      layout="prev, pager, next, jumper, ->, sizes, total"
      @current-change="getHasUser"
      @size-change="handler"
    />

    <!-- 新增/编辑对话框 -->
    <el-dialog v-model="dialogVisible" :title="title">
      <el-form label-width="80px" :model="userForm" ref="formRef">
        <el-form-item label="用户名" prop="username">
          <el-input v-model="userForm.username" :disabled="!!userForm.id" />
        </el-form-item>
        <el-form-item label="昵称" prop="name">
          <el-input v-model="userForm.name" />
        </el-form-item>
        <el-form-item label="密码" prop="password">
          <el-input
            v-model="userForm.password"
            type="password"
            show-password
            :placeholder="userForm.id ? '留空则不修改密码' : '请输入密码'"
          />
        </el-form-item>
      </el-form>
      <template #footer>
        <el-button @click="dialogVisible = false">取消</el-button>
        <el-button type="primary" @click="save">确定</el-button>
      </template>
    </el-dialog>

    <!-- 分配角色对话框 -->
    <el-dialog v-model="assignVisible" title="分配角色">
      <el-checkbox v-model="checkAll" :indeterminate="isIndeterminate" @change="handleCheckAll">
        全选
      </el-checkbox>
      <el-checkbox-group v-model="checkedRoles" @change="handleCheckedChange">
        <el-checkbox v-for="role in allRoles" :key="role.id" :value="role.id">
          {{ role.roleName }}
        </el-checkbox>
      </el-checkbox-group>
      <template #footer>
        <el-button @click="assignVisible = false">取消</el-button>
        <el-button type="primary" @click="confirmAssign">确定</el-button>
      </template>
    </el-dialog>
  </el-card>
</template>

<script setup lang="ts">
import { ref, reactive, onMounted } from 'vue'
import { ElMessage } from 'element-plus'
import 'element-plus/es/components/message/style/css'
import {
  reqGetUserList,
  reqAddUser,
  reqUpdateUser,
  reqRemoveUser,
  reqGetUserRoles,
  reqAssignUserRoles,
} from '@/api/acl/user'
import type { components } from '@/api/schema'

type User = components['schemas']['types.User']
type ResponseToAssignRole = components['schemas']['types.ResponseToAssignRole']

// —— 列表状态 ——
const userList = ref<User[]>([])
const total = ref(0)
const pageNo = ref(1)
const pageSize = ref(5)
const keyword = ref('')
const loading = ref(false)
const selectIds = ref<number[]>([])

// —— 新增/编辑 ——
const dialogVisible = ref(false)
const title = ref('添加用户')
const userForm = reactive<{
  id?: number
  username: string
  name: string
  password: string
}>({ username: '', name: '', password: '' })

// —— 分配角色 ——
const assignVisible = ref(false)
const allRoles = ref<ResponseToAssignRole['allRolesList']>([])
const checkedRoles = ref<number[]>([])
const checkAll = ref(false)
const isIndeterminate = ref(false)
let assignUserId = 0

onMounted(getHasUser)

async function getHasUser() {
  loading.value = true
  try {
    const { data } = await reqGetUserList(pageNo.value, pageSize.value, keyword.value)
    userList.value = data?.data.records ?? []
    total.value = data?.data.total ?? 0
  } finally {
    loading.value = false
  }
}

function handler() {
  getHasUser()
}
function search() {
  pageNo.value = 1
  getHasUser()
}
function reset() {
  keyword.value = ''
  pageNo.value = 1
  getHasUser()
}

function handleSelection(rows: ResponseUser[]) {
  selectIds.value = rows.map((r) => r.id)
}

// —— 新增/编辑 ——
function openAdd() {
  title.value = '添加用户'
  Object.assign(userForm, { id: undefined, username: '', name: '', password: '' })
  dialogVisible.value = true
}
function openEdit(row: ResponseUser) {
  title.value = '编辑用户'
  Object.assign(userForm, {
    id: row.id,
    username: row.username,
    name: row.name,
    password: '',
  })
  dialogVisible.value = true
}
async function save() {
  try {
    if (userForm.id) {
      // 编辑：id 必填，密码留空则不提交该字段
      const payload: { id: number; username: string; name: string; password?: string } = {
        id: userForm.id,
        username: userForm.username,
        name: userForm.name,
      }
      if (userForm.password) payload.password = userForm.password
      await reqUpdateUser(payload)
    } else {
      // 新增：username/name/password 后端必填
      await reqAddUser({
        username: userForm.username,
        name: userForm.name,
        password: userForm.password,
      })
    }
    ElMessage.success(userForm.id ? '更新成功' : '添加成功')
    dialogVisible.value = false
    getHasUser()
  } catch {
    // 中间件已 ElMessage.error 提示，这里仅阻止后续流程
  }
}

// —— 删除 ——
async function removeUser(row: User) {
  try {
    await reqRemoveUser(row.id)
    ElMessage.success('删除成功')
    // 删除后若当前页空了，回退一页
    if (userList.value.length === 1 && pageNo.value > 1) pageNo.value--
    getHasUser()
  } catch {
    // 中间件已提示错误
  }
}

// —— 分配角色 ——
async function openAssign(row: User) {
  try {
    assignUserId = row.id
    const { data } = await reqGetUserRoles(assignUserId)
    allRoles.value = data?.data.allRolesList ?? []
    checkedRoles.value = (data?.data.assignRoles ?? []).map((r) => r.id as number)
    syncCheckAll()
    assignVisible.value = true
  } catch {
    // 中间件已提示错误
  }
}
function syncCheckAll() {
  const total = allRoles.value.length
  checkAll.value = total > 0 && checkedRoles.value.length === total
  isIndeterminate.value = checkedRoles.value.length > 0 && checkedRoles.value.length < total
}
function handleCheckAll(val: boolean) {
  checkedRoles.value = val ? allRoles.value.map((r) => r.id) : []
  isIndeterminate.value = false
}
function handleCheckedChange() {
  syncCheckAll()
}
async function confirmAssign() {
  try {
    await reqAssignUserRoles(assignUserId, checkedRoles.value)
    ElMessage.success('分配成功')
    assignVisible.value = false
    getHasUser()
  } catch {
    // 中间件已提示错误
  }
}
</script>
```

> **要点**：`ElMessage` 需**显式** `import { ElMessage } from 'element-plus'` + `import 'element-plus/es/components/message/style/css'`（本项目没配自动导入，漏了样式会丢）；编辑用户时密码空 = 不改密码，编辑分支用 `if (userForm.password) payload.password = ...` 条件添加；`el-checkbox` 用 `:value` 绑值、插槽放文字（Element Plus 2.x 写法）。时间字段后端可能不返回，用 `row.createTime || '-'` 兜底。

import type { components } from '@/api/schema'

type Role = components['schemas']['types.Role']
type Menu = components['schemas']['types.Menu']

const roleList = ref<Role[]>([])
const total = ref(0)
const pageNo = ref(1)
const pageSize = ref(5)
const keyword = ref('')
const loading = ref(false)

const dialogVisible = ref(false)
const title = ref('添加角色')
const roleForm = reactive<{ id?: number; roleName: string; remark: string }>({
  roleName: '',
  remark: '',
})

const assignVisible = ref(false)
const menuTree = ref<Menu[]>([])
const checkedKeys = ref<number[]>([])

  loading.value = true
  try {
    const { data } = await reqGetRoleList(pageNo.value, pageSize.value, keyword.value)
    roleList.value = data?.data.records ?? []
    total.value = data?.data.total ?? 0
  } finally {
    loading.value = false
  }
}

  pageNo.value = 1
  getHasRole()
}
function reset() {
  keyword.value = ''
  pageNo.value = 1
  getHasRole()
}

  title.value = '添加角色'
  Object.assign(roleForm, { id: undefined, roleName: '', remark: '' })
  dialogVisible.value = true
}
function openEdit(row: Role) {
  title.value = '编辑角色'
  Object.assign(roleForm, { id: row.id, roleName: row.roleName, remark: row.remark })
  dialogVisible.value = true
}
async function save() {
  try {
    if (roleForm.id) {
      const payload: RoleUpdateForm = {
        id: roleForm.id,
        roleName: roleForm.roleName,
        remark: roleForm.remark,
      }
      await reqUpdateRole(payload)
    } else {
      const payload: RoleSaveForm = {
        roleName: roleForm.roleName,
        remark: roleForm.remark,
      }
      await reqAddRole(payload)
    }
    ElMessage.success('操作成功')
    dialogVisible.value = false
    getHasRole()
  } catch {
    // 中间件已提示错误
  }
}
async function removeRole(row: Role) {

    await reqRemoveRole(row.id)
    ElMessage.success('删除成功')
    if (roleList.value.length === 1 && pageNo.value > 1) pageNo.value--
    getHasRole()
  } catch {
    // 中间件已提示错误
  }

  try {
    assignRoleId = row.id
    const { data } = await reqGetRoleMenus(assignRoleId)
    menuTree.value = data?.data ?? []
    // 收集所有 select=true 的节点 id（含父子）
    const ids: number[] = []
    const walk = (nodes: Menu[]) => {
      nodes.forEach((n) => {
        if (n.select) ids.push(n.id)
        if (n.children) walk(n.children)
      })
    }
    walk(menuTree.value)
    checkedKeys.value = ids
    assignVisible.value = true
  } catch {
    // 中间件已提示错误
  }
}
function onTreeOpened() {
  // 弹窗展开后再设置默认勾选，确保 tree 已渲染
  treeRef.value?.setCheckedKeys(checkedKeys.value)
}

  try {
    const checked = treeRef.value?.getCheckedKeys() ?? []
    const half = treeRef.value?.getHalfCheckedKeys() ?? []
    await reqAssignRoleMenus(assignRoleId, [...checked, ...half])
    ElMessage.success('分配成功')
    assignVisible.value = false
  } catch {
    // 中间件已提示错误
  }
}

### 8.1 接口层 `src/api/acl/permission/index.ts` {#s8-1}

> 类型全部来自 `src/api/schema.d.ts`（见第 1 章），本文件只放薄封装函数。

```ts
import { client } from '@/api/client'
import type { components } from '@/api/schema'

type Menu = components['schemas']['types.Menu']

// 菜单权限树（GET /permission 返回 Menu[]）
export const reqGetMenuList = () => client.GET('/api/v1/acl/permission')

// 根据角色获取菜单树（含 select 标记）：GET /permission/role/{roleId} 返回 Menu[]
export const reqGetRoleMenus = (roleId: number) =>
  client.GET(`/api/v1/acl/permission/role/${roleId}`)

// ⚠️ 给角色分配权限：permissionId 是 query 参数（csv 拼接），不是 body
export const reqAssignRoleMenus = (roleId: number, permissionId: number[]) =>
  client.POST(`/api/v1/acl/permission/role/${roleId}`, {
    params: { query: { permissionId: permissionId.join(',') } },
  })

export const reqAddMenu = (data: Partial<Menu>) =>
  client.POST('/api/v1/acl/permission', { body: data })

export const reqUpdateMenu = (data: Partial<Menu>) =>
  client.PUT(`/api/v1/acl/permission/${data.id}`, { body: data })

export const reqRemoveMenu = (id: number) => client.DELETE(`/api/v1/acl/permission/${id}`)
```

## 学习要点总结 {#slearn}

| 要点                                                            | 关键代码                                                                                       | 说明                                                                                                                                                                                                   |
| --------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **请求走统一 client**                                          | `client.GET/POST/PUT/DELETE('/api/v1/acl/...', { params, body })`                            | 项目封装在 `src/api/client.ts`（openapi-fetch），类型来自 `schema.d.ts`；无手写 axios/拦截器；返回 `{ data, error }` 元组                                      |
| **类型来自 schema，不手写**                                     | `type User = components['schemas']['types.User']`                                             | 领域类型全在 `src/api/schema.d.ts`，由 swagger 生成；**不要**新建 `api/type.ts`/`api/acl/type.ts`；路径前缀统一 `/api/v1/acl/*`                                      |
| **接口层零 `any`**                                              | `client.GET('/api/v1/acl/user', { params: { query: {...} } })`                               | openapi-fetch 按 schema 自动推导入参/出参类型，页面 `ref<User[]>([])` 与之串联，全程零 `any`                                                                       |
| **`ref`/`reactive` 用泛型定状态形状**                           | `ref<User[]>([])`、`reactive<{ id?: number; ... }>({...})`                                   | 空数组会被推断成 `never[]`（push 报错），初始对象缺字段（如 `userForm.id`）会"不存在"；显式泛型在类型不足时补全，避免后期取数/赋值编译期报错                                                       |
| **泛型 = 编译期类型安全，提前挡错**                             | `client.GET` 出参与页面 `ref<...>` 用同一套 schema 类型串联                                   | 把"字段名写错 / 类型不匹配 / 访问不存在字段 / 取数路径拼错"这类高频低级错误从运行时提前到保存时即报错；但 TS 只管编译期，运行时后端结构异常仍靠中间件兜底                                          |
| **字段类型严格对齐后端契约**                                    | `menuForm` 的 `level`/`type` 用 `number`                                                     | 契约里 `level`/`type` 是数字（`code` 才是 string）；`menuForm` 表单字段也必须是 `number`，否则 `payload` 赋值处报 `string` 不能赋给 `number`；初始值与 `openAdd` 里直接传数字，不要 `String()` 转换  |
| **`/permission/role/{roleId}` 的 `permissionId` 是 query 参数** | `params: { query: { permissionId: idList.join(',') } }`                                       | 写成 body 会 201；client 对字符串 query 不二次展开，正好成 csv                                                                                                                                      |
| **`el-tree` 分配权限**                                          | `check-strictly` + `getCheckedKeys()` + `getHalfCheckedKeys()`                               | 父子不联动，确认时合并全选+半选节点                                                                                                                                                                  |
| **`ElMessage` 需显式 import**                                   | `import { ElMessage } from 'element-plus'` + `import 'element-plus/es/components/message/style/css'` | 本项目未配自动导入，漏了样式会丢（阶段 5 结论）                                                                                                                  |
| **编辑用户密码可选**                                            | `save()` 编辑分支 `if (userForm.password) payload.password = ...`                            | 密码留空则 payload 不带 `password` 字段，后端 `update` 只需 `{id,username,name}`，密码留空=不改                                                                                                    |
| **异步操作要 try/catch 兜底**                                   | `getHasUser` 用 `try/finally` 复位 `loading`，`save`/`removeXxx` 用 `try/catch` 阻止错误后继续 | 中间件已弹错误并 throw，catch 空处理即可；否则接口报错会卡在 `loading` 或误弹成功提示                                                                                                            |
| **分配类接口是子资源，函数名各异**                              | 用户页 `reqGetUserRoles`(user) / 角色页 `reqGetRoleMenus`(permission)                        | `reqGetUserRoles`（user 模块，GET /user/{userId}/role 取角色）与 `reqGetRoleMenus`（permission 模块，GET /permission/role/{roleId} 取菜单树）是两个不同函数、路径不同，别混淆                        |
| **错误已统一处理，catch 可空**                                  | `catch { /* 中间件已提示错误 */ }`                                                          | 因为非 200 已在 client 中间件里 `ElMessage.error` 并 throw，页面 catch 里不用再提示，写个注释的空 catch 即可；catch 后不接变量名（`catch {}`）是 ES2019+ 合法写法                               |
| **时间字段可选、兜底渲染**                                      | `{{ row.createTime \|\| '-' }}`                                                              | `User`/`Role` 的 `createTime?` 后端在字段为空时不返回（swagger 契约），故类型用 `?`；缺省显示 `-`，避免界面出现 `undefined`；无需引入额外 `formatTime` 工具               |

## 常见报错排查 {#serr}

| 现象                                | 原因                                                                     | 解决                                                                                                                                 |
| ----------------------------------- | ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------ |
| 分配权限提交后无变化 / 控制台报 201 | 把 `permissionId` 写成 JSON body                                         | 改成 query 参数：`client.POST(url, { params: { query: { permissionId: idList.join(',') } } })`                                        |
| 页面取数 `undefined`                | 直接用了返回值当业务数据                                                 | `client` 返回 `{ data, error }`，业务字段在 `data.data`（包裹对象），取 `data?.data.records` 等                                        |
| `ElMessage` 弹窗纯白无样式          | 只 `import { ElMessage }` 漏了样式                                       | 补 `import 'element-plus/es/components/message/style/css'`；本项目未配自动导入                                                         |
| 删除菜单报 208「节点下有子节点」    | 该菜单含子节点                                                           | 先删子节点，或后端加级联删除接口                                                                                                     |
| 角色权限勾选后再次打开不全          | 只提交 `getCheckedKeys()` 漏了半选父节点                                 | 合并 `getHalfCheckedKeys()` 一起提交                                                                                                 |
| `el-checkbox` 不显示文字            | 用了旧版 `label` 绑值                                                    | EP 2.x 用 `:value` 绑值、默认插槽放文字                                                                                              |
| 点菜单项高亮变了但路由不跳转        | 递归 `SideMenu` 出现了**嵌套** `<el-menu>`（每层各包一个），内层 el-menu 吞掉 `click` 事件 | 整个侧边栏只保留**一个** `<el-menu>`（根实例包，递归子实例只渲染 `el-menu-item`/`el-sub-menu`，不要再加 el-menu）；点击用 `@click` 手动 `$router.push`；本项目 `SideMenu` 已是单根结构，正常情况下不会触发此问题 |
