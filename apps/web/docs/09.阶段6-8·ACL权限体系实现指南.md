## 0. 后端契约总览 {#s0}

所有请求走 `src/utils/request.ts`，其响应拦截器在 `code===200` 时 **返回整个包裹对象** `{ code, data, message }`（见 `request.ts` 落地后的拦截器实现；与 `05.前后端交互数据规范.md` 的响应结构保持一致）。因此：

- **接口层函数返回类型**是 `ResponseData<T>`（包裹对象），不是裸 `T`；
- **页面里取业务数据一律 `res.data`**；
- `code!==200` 时拦截器已自动 `ElMessage.error(message)` 并 reject，页面无需重复提示，只需 `try/catch` 或在 `.catch` 里阻止后续流程。

token 由请求拦截器自动从 `localStorage` 读 `token` 字段塞进 `headers.token`，接口层无需关心。

### 0.1 响应结构

```ts
interface ResponseData<T> {
  code: number // 200 成功；鉴权失败 110002（未登录）/ 110003（token 失效）；其余业务码见 pkg/result/code.go。所有响应 HTTP 状态恒为 200，必须解析本字段
  // ⚠️ 旧版示例的 201/202/203/204/208 在本仓库不沿用
  data: T
  message: string
}
```

### 0.2 各模块接口清单

**用户 `/admin/acl/user`**

| 方法   | 路径                  | 入参                                               | 返回 `data`                                                                 | 作用                                                  |
| ------ | --------------------- | -------------------------------------------------- | --------------------------------------------------------------------------- | ----------------------------------------------------- |
| GET    | `/admin/acl/user`               | query `page,limit,username?`                       | `ResponseUserList { records: ResponseUser[]; total; size; current; pages }` | 分页查询用户列表；`username` 为空则查全部             |
| POST   | `/admin/acl/user`               | body `{ username, name, password }`（必填）        | `null`                                                                      | 新增用户，三字段必填                                   |
| PUT    | `/admin/acl/user`      | body `{ id, username, name }`（**id 在 body，非路径**） | `null`                                                                      | 修改用户                                              |
| DELETE | `/admin/acl/user/:userId`      | path                                               | `null`                                                                      | 删除单个用户                                          |
| GET    | `/admin/acl/user/:userId/role` | path                                               | `ResponseToAssignRole { allRolesList: Role[]; assignRoles: Role[] }`        | 打开「分配角色」前拉数据：全部角色 + 该用户已分配角色 |
| POST   | `/admin/acl/user/:userId/role` | body `{ userId: number; roleIdList: number[] }`    | `null`                                                                      | 确认把用户绑定到选中的多个角色                        |
| GET    | `/admin/acl/user/info` | — | `ResponseUserInfo { avatar; buttons[]; name; roles[]; routes[] }` | 当前登录用户信息（路径已确认，以常量 `USERINFO_URL` 为准，不要散写硬编码） |

> `ResponseUser` 字段：`id, username, name, password, phone, roleName, createTime?, updateTime?`（`createTime` / `updateTime` 为可选，后端在字段为空时不返回该字段）；`ResponseUserInfo`：`avatar, buttons[], name, roles[], routes[]`。

**角色 `/admin/acl/role`**

| 方法   | 路径             | 入参                                        | 返回 `data`                                                         | 作用                                      |
| ------ | ---------------- | ------------------------------------------- | ------------------------------------------------------------------- | ----------------------------------------- |
| GET    | `/role`          | query `page,limit,roleName?`                | `ResponseRoleList { records: Role[]; total; size; current; pages }` | 分页查询角色列表；`roleName` 为空则查全部 |
| POST   | `/role`          | body `{ roleName, remark? }`                | `null`                                                              | 新增角色，`remark` 备注可选               |
| PUT    | `/role/{roleId}` | body `{ id, roleName, remark? }`（路径 id） | `null`                                                              | 修改角色                                  |
| DELETE | `/role/{roleId}` | path                                        | `null`                                                              | 删除角色                                  |

> `Role` 字段：`id, roleName, remark, createTime?, updateTime?`（`createTime` / `updateTime` 为可选，后端在字段为空时不返回该字段）。

**菜单/权限 `/admin/acl/permission`**

| 方法   | 路径                         | 入参                                     | 返回 `data`                                 | 作用                                                  |
| ------ | ---------------------------- | ---------------------------------------- | ------------------------------------------- | ----------------------------------------------------- |
| GET    | `/permission`                | —                                        | `Menu[]`（树，`children` 嵌套）             | 拉整棵权限菜单树                                      |
| GET    | `/permission/role/{roleId}`  | path                                     | `Menu[]`（树，已分配节点带 `select: true`） | 打开「分配权限」前拉数据，已勾选节点带 `select: true` |
| POST   | `/permission/role/{roleId}`  | **query** `permissionId`(int 数组, csv)  | `null`                                      | 确认把权限树绑定给角色（⚠️ query 参数，非 body）      |
| POST   | `/permission`                | body `{ name, code?, level, pid, type }` | `null`                                      | 新增菜单/按钮权限节点                                 |
| PUT    | `/permission/{permissionId}` | body `{ id, name, code?, level, pid }`   | `null`                                      | 修改某个权限节点                                      |
| DELETE | `/permission/{permissionId}` | path                                     | `null`（有子节点时 `code` 返回业务错误码，非 HTTP 208） | 删除权限节点；有子节点后端拒绝并给错误 `code`                 |

> `Menu` 字段：`id, pid, name, code, level, type, status, toCode, select?, children?`。`type`：1=一级菜单，2=二级菜单，3=按钮功能；`level`：1/2/3 对应层级。`code` 为字符串、`level`/`type` 为数字（新 REST 契约；旧版 `code` 为数字、`level`/`type` 为字符串）。

⚠️ **最易踩的坑：`POST /permission/role/{roleId}` 的 `permissionId` 是 query 参数，不是 body！** 我们用 curl 实测：把 `permissionId` 拼在 URL 上（`?permissionId=1,7,8,...`）才返回 200，任何写成 JSON body 的尝试都返回 201 参数错误。所以接口层要写成：

```ts
request.post(`/admin/acl/permission/role/${roleId}`, null, {
  params: { permissionId: permissionId.join(',') },
})
```

（axios 对字符串 `params` 不会二次展开，正好形成 `permissionId=1,7,8` 的 csv 形式。）

### 1.2 ACL 领域类型 `src/api/acl/type.ts` {#s12}

用户 / 角色 / 菜单三个模块的**所有类型**集中在此一个文件：共享业务类型 + 各模块入参/出参类型。子模块接口层只放函数，统一 `from '@/api/acl/type'` 引类型（`@` 即 `src`，无需相对路径）。

```ts
// src/api/acl/type.ts
import type { ResponseData } from '@/api/type'

// ———————— 角色模块（纯角色 CRUD）————————
export interface Role {
  id: number
  roleName: string
  remark: string
  createTime?: string
  updateTime?: string
}

// 角色分页
export interface ResponseRoleList {
  records: Role[]
  total: number
  size: number
  current: number
  pages: number
  searchCount: boolean
}

// 角色模块入参
export interface RoleSaveForm {
  roleName: string
  remark?: string
}
export interface RoleUpdateForm {
  id: number
  roleName: string
  remark?: string
}

export type RoleListResponse = ResponseData<ResponseRoleList>

// ———————— 用户模块（用户 CRUD + 分配角色）————————
export interface ResponseUser {
  id: number
  username: string
  name: string
  password: string
  phone: string
  roleName: string
  createTime?: string
  updateTime?: string
}

export interface ResponseUserList {
  records: ResponseUser[]
  total: number
  size: number
  current: number
  pages: number
  // 新 REST 契约 ResponseUserList 不含 searchCount
}

// 用户模块入参
export interface UserSaveForm {
  username: string
  name: string
  password: string
}
export interface UserUpdateForm {
  id: number
  username: string
  name: string
  // 新 REST 契约更新用户不含 password
}

// 给用户分配角色：GET /user/{userId}/role 返回的可分配角色与已分配角色
// 注意字段名为复数（与后端一致）：allRolesList / assignRoles
export interface ResponseToAssignRole {
  allRolesList: Role[]
  assignRoles: Role[]
}

export type UserListResponse = ResponseData<ResponseUserList>
export type ToAssignRoleResponse = ResponseData<ResponseToAssignRole>
export type AssignRoleResponse = ResponseData<null>
export type SaveResponse = ResponseData<string>

// 当前登录用户信息：GET /user/info
export interface ResponseUserInfo {
  avatar: string
  buttons: string[]
  name: string
  roles: string[]
  routes: string[]
}
export type UserInfoResponse = ResponseData<ResponseUserInfo>

// ———————— 菜单/权限模块 ————————
// 树节点（select / children 仅在特定接口返回，故保留 ?）
// 注意：新 REST 契约 Menu 的 code 为 string，level / type 为 number
export interface Menu {
  id: number
  pid: number
  name: string
  code: string
  level: number
  type: number
  status: number
  toCode: string
  children?: Menu[]
  select?: boolean
}

// 菜单模块入参
export interface MenuSaveForm {
  name: string
  pid: number
  code?: string
  level: number
  type: number
}
export interface MenuUpdateForm {
  id: number
  name: string
  code?: string
  level: number
  pid: number
  // 新 REST 契约更新菜单不含 type
}
// GET /permission 返回菜单树数组（_ResponseMenuList.data 为 Menu[]）
export type MenuTreeResponse = ResponseData<Menu[]>
// GET /permission/role/{roleId} 返回 _ResponseToAssignMenuList，data 为 Menu[]
export type RoleMenuListResponse = ResponseData<Menu[]>

// ———————— 公共出参（三模块共用）————————
export type CommonResponse = ResponseData<null>
```

## 阶段 6：用户管理 {#s6}

### 6.1 接口层 `src/api/acl/user/index.ts` {#s6-1}

> 类型全部来自 `src/api/acl/type.ts`（已在 1.2 定义），本文件只放接口函数，统一 `from '@/api/acl/type'` 引类型。

```ts
import request from '@/utils/request'
import type {
  ResponseUserList,
  UserListResponse,
  ToAssignRoleResponse,
  AssignRoleResponse,
  CommonResponse,
  SaveResponse,
  UserInfoResponse,
  UserSaveForm,
  UserUpdateForm,
} from '@/api/acl/type'

// 模块内 URL 集中（写法 4：路径参数用函数流出，调用处不再拼接字符串）
const BASE = '/admin/acl/user'
const URL = {
  LIST: BASE, // GET 分页 ?page&limit&username；POST 新增
  DETAIL: (id: number) => `${BASE}/${id}`,
  BATCH_DELETE: `${BASE}/batch-delete`,
  ROLE: (userId: number) => `${BASE}/${userId}/role`,
  INFO: `${BASE}/info`, // GET 当前用户信息
}

// 用户分页列表（分页走 query；username 为空则查全部）
//   泛型：<响应体 T, 返回 R, 请求体 D>；第二参 R = ResponseData<...> 才是真正返回的 Promise 类型
export const reqGetUserList = (page: number, limit: number, username: string) =>
  request.get<ResponseUserList, UserListResponse>(URL.LIST, {
    params: { page, limit, username },
  })

// 新增用户（save 返回的 data 是 string）
export const reqAddUser = (data: UserSaveForm) =>
  request.post<string, SaveResponse, UserSaveForm>(URL.LIST, data)

// 修改用户：路径 id 取自 body.id
export const reqUpdateUser = (data: UserUpdateForm) =>
  request.put<unknown, CommonResponse, UserUpdateForm>(URL.DETAIL(data.id), data)

// 删除用户
export const reqRemoveUser = (id: number) => request.delete<unknown, CommonResponse>(URL.DETAIL(id))

// 批量删除（body 传 id 数组）
export const reqBatchRemoveUser = (idList: number[]) =>
  request.post<unknown, CommonResponse, number[]>(URL.BATCH_DELETE, idList)

// 当前登录用户信息
export const reqGetUserInfo = () => request.get<ResponseUserInfo, UserInfoResponse>(URL.INFO)

// 获取某用户已分配/全部角色：GET /user/{userId}/role
export const reqGetUserRoles = (userId: number) =>
  request.get<ResponseToAssignRole, ToAssignRoleResponse>(URL.ROLE(userId))

// 给用户分配角色：POST /user/{userId}/role
export const reqAssignUserRoles = (userId: number, roleIdList: number[]) =>
  request.post<unknown, AssignRoleResponse, { userId: number; roleIdList: number[] }>(
    URL.ROLE(userId),
    { userId, roleIdList },
  )
```

```vue
<script setup lang="ts">
import { ref, reactive, onMounted } from 'vue'
import { formatTime } from '@/utils/time'
import {
  reqGetUserList,
  reqAddUser,
  reqUpdateUser,
  reqRemoveUser,
  reqBatchRemoveUser,
  reqGetUserRoles,
  reqAssignUserRoles,
} from '@/api/acl/user'
import type { ResponseUser, UserSaveForm, UserUpdateForm } from '@/api/acl/type'

// —— 列表状态 ——
const userList = ref<ResponseUser[]>([])
const total = ref(0)
const pageNo = ref(1)
const pageSize = ref(5)
const keyword = ref('')
const loading = ref(false)
const selectIds = ref<number[]>([])

// —— 新增/编辑 ——
const dialogVisible = ref(false)
const title = ref('添加用户')
const userForm = reactive<{
  id?: number
  username: string
  name: string
  password: string
}>({ username: '', name: '', password: '' })

// —— 分配角色 ——
const assignVisible = ref(false)
const allRoles = ref<{ id?: number; roleName?: string }[]>([])
const checkedRoles = ref<number[]>([])
const checkAll = ref(false)
const isIndeterminate = ref(false)
let assignUserId = 0

onMounted(getHasUser)

async function getHasUser() {
  loading.value = true
  try {
    const res = await reqGetUserList(pageNo.value, pageSize.value, keyword.value)
    userList.value = res.data.records
    total.value = res.data.total
  } finally {
    loading.value = false
  }
}

function handler() {
  getHasUser()
}
function search() {
  pageNo.value = 1
  getHasUser()
}
function reset() {
  keyword.value = ''
  pageNo.value = 1
  getHasUser()
}

function handleSelection(rows: ResponseUser[]) {
  selectIds.value = rows.map((r) => r.id)
}

// —— 新增/编辑 ——
function openAdd() {
  title.value = '添加用户'
  Object.assign(userForm, { id: undefined, username: '', name: '', password: '' })
  dialogVisible.value = true
}
function openEdit(row: ResponseUser) {
  title.value = '编辑用户'
  Object.assign(userForm, {
    id: row.id,
    username: row.username,
    name: row.name,
    password: '',
  })
  dialogVisible.value = true
}
async function save() {
  try {
    if (userForm.id) {
      // 编辑：id 必填，密码留空则不提交该字段
      const payload: UserUpdateForm = {
        id: userForm.id,
        username: userForm.username,
        name: userForm.name,
      }
      if (userForm.password) payload.password = userForm.password
      await reqUpdateUser(payload)
    } else {
      // 新增：username/name/password 后端必填
      const payload: UserSaveForm = {
        username: userForm.username,
        name: userForm.name,
        password: userForm.password,
      }
      await reqAddUser(payload)
    }
    ElMessage.success(userForm.id ? '更新成功' : '添加成功')
    dialogVisible.value = false
    getHasUser()
  } catch {
    // 拦截器已 ElMessage.error 提示，这里仅阻止后续流程
  }
}

// —— 删除 ——
async function removeUser(row: ResponseUser) {
  try {
    await reqRemoveUser(row.id)
    ElMessage.success('删除成功')
    // 删除后若当前页空了，回退一页
    if (userList.value.length === 1 && pageNo.value > 1) pageNo.value--
    getHasUser()
  } catch {
    // 拦截器已提示错误
  }
}
async function batchDelete() {
  try {
    await reqBatchRemoveUser(selectIds.value)
    ElMessage.success('批量删除成功')
    getHasUser()
  } catch {
    // 拦截器已提示错误
  }
}

// —— 分配角色 ——
async function openAssign(row: ResponseUser) {
  try {
    assignUserId = row.id
    const res = await reqGetUserRoles(assignUserId)
    allRoles.value = res.data.allRolesList
    checkedRoles.value = res.data.assignRoles.map((r) => r.id)
    syncCheckAll()
    assignVisible.value = true
  } catch {
    // 拦截器已提示错误
  }
}
function syncCheckAll() {
  const total = allRoles.value.length
  checkAll.value = total > 0 && checkedRoles.value.length === total
  isIndeterminate.value = checkedRoles.value.length > 0 && checkedRoles.value.length < total
}
function handleCheckAll(val: boolean) {
  checkedRoles.value = val ? allRoles.value.map((r) => r.id) : []
  isIndeterminate.value = false
}
function handleCheckedChange() {
  syncCheckAll()
}
async function confirmAssign() {
  try {
    await reqAssignUserRoles(assignUserId, checkedRoles.value)
    ElMessage.success('分配成功')
    assignVisible.value = false
    getHasUser()
  } catch {
    // 拦截器已提示错误
  }
}
</script>
```

> **要点**：`ElMessage` 不要手动 `import`，靠 `unplugin-auto-import` 自动导入才会连带注入样式（阶段 5 踩过的坑）；编辑用户时密码空 = 不改密码，编辑分支用 `if (userForm.password) payload.password = ...` 条件添加，密码留空则 `UserUpdateForm` 不带 `password` 字段；`el-checkbox` 用 `:value` 绑值、插槽放文字（Element Plus 2.x 写法）。

## 学习要点总结 {#slearn}

| 要点                                                            | 关键代码                                                                                       | 说明                                                                                                                                                                                                   |
| --------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **响应拦截器返回包裹对象**                                      | `request.ts:46` `return response.data`                                                         | 接口层返回 `ResponseData<T>`（定义在 `src/api/type.ts`，全局通用），页面统一 `res.data` 取数                                                                                                           |
| **三层 ACL 共用一套契约**                                       | `user` / `role` / `permission` 三个 api 模块                                                   | 领域类型抽到 `acl/type.ts`；`ResponseData<T>` 提到全局 `api/type.ts`；路径前缀统一 `/admin/acl/*`                                                                                                      |
| **接口层泛型不用 `any`**                                        | `request.get<响应体, 返回R, 请求体D>`                                                          | 第一参给真实响应体类型（或直接 `unknown`），第二参 `R` = `ResponseData<...>`（真正返回类型），POST/PUT 用第三参 `D` 约束请求体，全程零 `any`                                                           |
| **`ref`/`reactive` 用泛型定状态形状**                           | `ref<ResponseUser[]>([])`、`reactive<{ id?: number; ... }>({...})`                             | 空数组会被推断成 `never[]`（push 报错），初始对象缺字段（如 `userForm.id`）会"不存在"；显式泛型在类型不足时补全，避免后期取数/赋值编译期报错                                                           |
| **泛型 = 编译期类型安全，提前挡错**                             | 接口层 `<T,R,D>` 与页面 `ref<...>`/`reactive<...>` 用同一套类型串联                            | 把"字段名写错 / 类型不匹配 / 访问不存在字段 / 取数路径拼错"这类高频低级错误从运行时提前到保存时即报错；但 TS 只管编译期，运行时后端结构异常仍靠拦截器兜底                                              |
| **字段类型严格对齐后端契约**                                    | 菜单 `MenuSaveForm`/`MenuUpdateForm` 的 `level`/`type` 用 `number`                             | 契约里 `level`/`type` 是数字（`code` 才是 string）；`menuForm` 表单字段也必须是 `number`，否则 `payload` 赋值处报 `string` 不能赋给 `number`；初始值与 `openAdd` 里直接传数字，不要 `String()` 转换    |
| **`/permission/role/{roleId}` 的 `permissionId` 是 query 参数** | `permission/index.ts` `params:{ permissionId: idList.join(',') }`                              | 写成 body 会 201；axios 对字符串 param 不二次展开，正好成 csv                                                                                                                                          |
| **`el-tree` 分配权限**                                          | `check-strictly` + `getCheckedKeys()` + `getHalfCheckedKeys()`                                 | 父子不联动，确认时合并全选+半选节点                                                                                                                                                                    |
| **`ElMessage` 走自动导入**                                      | 页面里不写 `import`                                                                            | 否则弹窗丢样式（阶段 5 结论）                                                                                                                                                                          |
| **编辑用户密码可选**                                            | `save()` 编辑分支 `if (userForm.password) payload.password = ...`                              | 密码留空则 payload 不带 `password` 字段，后端 `update` 只需 `{id,username,name}`，密码留空=不改                                                                                                        |
| **异步操作要 try/catch 兜底**                                   | `getHasUser` 用 `try/finally` 复位 `loading`，`save`/`removeXxx` 用 `try/catch` 阻止错误后继续 | 拦截器已弹错误，catch 空处理即可；否则接口报错会卡在 `loading` 或误弹成功提示                                                                                                                          |
| **分配类接口是子资源，函数名各异**                              | 用户页 `reqGetUserRoles`(user) / 角色页 `reqGetRoleMenus`(permission)                          | `reqGetUserRoles`（user 模块，GET /user/{userId}/role 取角色）与 `reqGetRoleMenus`（permission 模块，GET /permission/role/{roleId} 取菜单树）是两个不同函数、路径不同，别混淆                          |
| **错误已统一处理，catch 可空**                                  | `catch { /* 拦截器已提示错误 */ }`                                                             | 因为非 200 已在响应拦截器里 `ElMessage.error` 并 reject，页面 catch 里不用再提示，写个注释的空 catch 即可；catch 后不接变量名（`catch {}`）是 ES2019+ 合法写法                                         |
| **时间字段可选、用 `formatTime` 兜底渲染**                      | `import { formatTime } from '@/utils/time'` + `{{ formatTime(row.createTime) }}`               | `Role` / `ResponseUser` 的 `createTime?` / `updateTime?` 后端在字段为空时不返回（swagger 契约），故类型用 `?`；`formatTime` 零依赖，解析 RFC 3339 字符串，字段缺省时显示 `-`，避免界面出现 `undefined` |

## 常见报错排查 {#serr}

| 现象                                | 原因                                                                     | 解决                                                                                                                                 |
| ----------------------------------- | ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------ |
| 分配权限提交后无变化 / 控制台报 201 | 把 `permissionId` 写成 JSON body                                         | 改成 query 参数：`request.post(url, null, { params:{ roleId, permissionId: idList.join(',') } })`                                    |
| 页面取数 `undefined`                | 直接用了返回值当业务数据                                                 | 接口层返回的是包裹对象，取 `res.data`                                                                                                |
| `ElMessage` 弹窗纯白无样式          | 页面里手动 `import { ElMessage }`                                        | 删掉 import，交 AutoImport + ElementPlusResolver 自动导入                                                                            |
| 删除菜单报 208「节点下有子节点」    | 该菜单含子节点                                                           | 先删子节点，或后端加级联删除接口                                                                                                     |
| 角色权限勾选后再次打开不全          | 只提交 `getCheckedKeys()` 漏了半选父节点                                 | 合并 `getHalfCheckedKeys()` 一起提交                                                                                                 |
| `el-checkbox` 不显示文字            | 用了旧版 `label` 绑值                                                    | EP 2.x 用 `:value` 绑值、默认插槽放文字                                                                                              |
| 点菜单项高亮变了但路由不跳转        | 递归 `SideMenu` 每层各包一个 `<el-menu>`，嵌套 el-menu 吞掉 `click` 事件 | 整个侧边栏只保留**一个** `<el-menu>`（根实例包，递归子实例只渲染 `el-menu-item`/`el-sub-menu`）；点击用 `@click` 手动 `$router.push` |
