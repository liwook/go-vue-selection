# 02. 前端工程搭建与选型总结（Vue Admin）

> 本文档记录本项目从「集成 Element Plus」开始，**每一步做了什么、怎么操作的、为什么选这个库、以及它和同类库的对比**。
>
> 顺序：脚手架基线 → Element Plus → 自动按需导入（重点讲机制）→ 主题定制 → 图标 → 本地 SVG → 样式规范 → api 业务层（通用请求封装 `utils/request.ts` 见源码）→ 工程化规范 → 踩坑速查 → 端到端数据流。

---

## 前置：脚手架基线（决定后面所有选型）

本项目基线是 **Vite + Vue 3 + TypeScript**。

- **构建工具 Vite（而非 Webpack）**：基于浏览器原生 ESM，冷启动秒级、HMR 毫秒级；配置用 `defineConfig` 的 TS 对象，直观。代价是极老浏览器需额外 polyfill，但中后台内部系统通常不需要兼容 IE。
- **语言 TypeScript**：类型即文档，`vue-tsc` 在 `build` 时做全量类型检查，能在编译期拦住大量低级错误。
- 包管理 **pnpm**：硬链接节省磁盘、严格的依赖隔离（不会"幽灵依赖"），`packageManager` 字段锁定版本。

后面所有工具（unplugin 系列、Biome/ESLint 工程化…）都围绕 **Vite 插件生态** 与 **TS** 展开。

## 步骤一：集成 Element Plus（UI 组件库）

### 1.1 做了什么

```bash
pnpm add element-plus @element-plus/icons-vue
```

**它是什么**：UI 组件库——把按钮、表格、表单、弹窗、布局等后台常用界面元素封装成现成 Vue 组件，**引入即可用，不用自己写样式与交互逻辑**。

`src/main.ts` 中全量注册（后续靠"自动按需导入"插件按使用加载，全量注册仅作兜底）：

```ts
import ElementPlus from 'element-plus'
import 'element-plus/dist/index.css'
app.use(ElementPlus)
```

### 1.2 为什么用 Element Plus（对比主流 Vue 3 UI 库）

| 候选库                | 优点                                                                                                                | 缺点 / 不适场景                                       | 结论                 |
| --------------------- | ------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------- | -------------------- |
| **Element Plus** ✅   | Vue 3 官方续作；**组件最全**（Table/Form/Dialog/Layout 等后台刚需全覆盖）；中文文档友好；社区模板最多、踩坑资料最全 | 定制主题需走 Sass 变量；包体较大（靠按需导入缓解）    | **中后台首选**       |
| Ant Design Vue        | 设计规范严谨、组件精致、企业级感强                                                                                  | 风格偏"阿里系"，深度定制成本高；社区中文资料略少于 EP | 适合强设计规范的团队 |
| Naive UI              | 全 TS 编写、主题切换（暗黑模式）强、体积小、按需天然                                                                | 生态/现成后台模板少于 EP；部分复杂业务组件需自写      | 适合轻量、个性化项目 |
| Vant / NutUI          | 移动端组件库                                                                                                        | 桌面端布局/表格能力弱                                 | 不适用 PC 后台       |
| Arco Design / TDesign | 大厂出品、设计统一                                                                                                  | 生态成熟度与资料量仍不及 EP                           | 可备选               |

**选型理由一句话**：后台系统需要大量「表格 + 表单 + 弹窗 + 布局」开箱即用组件，Element Plus 在这块最成熟、模板最多、学习曲线最低，是性价比最高的选择。

## 步骤二：自动按需导入

### 2.1 装了什么

```bash
pnpm add -D unplugin-auto-import unplugin-vue-components
```

**它们是什么**：两个 Vite **编译期**插件。`unplugin-auto-import` 负责自动补 `<script>` 里函数/API 的 `import`；`unplugin-vue-components` 负责自动解析并注册 `<template>` 里的组件标签。共同目标：**写完即用，不用手写 import**。

### 2.2 在 vite.config.ts 里怎么配

```ts
import AutoImport from 'unplugin-auto-import/vite'
import Components from 'unplugin-vue-components/vite'
import { ElementPlusResolver } from 'unplugin-vue-components/resolvers'
import IconsResolver from 'unplugin-icons/resolver'

plugins: [
  AutoImport({
    resolvers: [
      ElementPlusResolver({ importStyle: 'sass' }),
      IconsResolver({ prefix: 'Icon', enabledCollections: ['ep', 'mdi'] }),
    ],
  }),
  Components({
    resolvers: [
      ElementPlusResolver({ importStyle: 'sass' }),
      IconsResolver({ prefix: 'Icon', enabledCollections: ['ep', 'mdi'] }),
    ],
  }),
  // Icons() 与 UnpluginSvgComponent() 见后续步骤
]
```

### 2.3 两个插件职责不同（关键！）

很多人以为"装一个就行"，其实它们管的是**不同层面**：

| 插件                        | 管什么                                        | 例子                                                                                   |
| --------------------------- | --------------------------------------------- | -------------------------------------------------------------------------------------- |
| **unplugin-auto-import**    | **`<script>` 里的 API / 函数**自动补 `import` | 写 `ElMessage.success()` 不用 `import { ElMessage }`（由 `ElementPlusResolver` 解析）；`ref` 等 Vue API 需在 `AutoImport` 里额外配 `imports: ['vue']` 才能免写 `import` |
| **unplugin-vue-components** | **`<template>` 里的组件标签**自动解析并注册   | 写 `<el-button>` 不用 `import`；写 `<IconEpEdit />` 自动定位图标                       |

### 2.4 核心机制：Resolver（解析器）

两个插件本身**不知道** Element Plus / 图标在哪，真正干活的是 **resolver**（解析器）。

**Resolver 就是一个函数**：插件扫描源码发现一个不认识的标识符（如 `ElButton`、`ElMessage`、`IconEpEdit`），就挨个问 resolver："这个你能解析吗？能的话从哪个模块导入？"

- **`ElementPlusResolver`**：
  - 看到 `ElButton` / `ElMessage` / `ElDialog` … → 返回从 `element-plus` 导入。
  - 配了 `importStyle: 'sass'` → 同时把对应组件的 **Sass 样式**也一起导入（这样才能配合步骤三的主题定制，否则样式不生效）。
- **`IconsResolver({ prefix: 'Icon', enabledCollections: ['ep','mdi'] })`**：
  - 命名规则：**`Icon` + 集合名 + 图标名** → 映射到 Iconify 的虚拟模块。
  - 例如 `IconEpEdit` → 从 `~icons/ep/edit` 导入；`IconMdiHome` → 从 `~icons/mdi/home` 导入。
  - `prefix: 'Icon'` 就是约定"以 Icon 开头的标签才当图标处理"。

### 2.5 它怎么"无中生有"——编译期注入 + 生成类型声明

运作时机是 **Vite 启动 / 构建时（编译期）**，不是运行时：

1. 插件扫描每个 `.vue` / `.ts` 文件里用到的标识符。
2. 对识别到的标识符，在文件顶部**自动插入对应的 `import` 语句**（你源码里看不见，但打包后的代码里有）。
3. 生成两个 **`.d.ts` 声明文件**，让 TypeScript 知道这些"没写 import 的东西"也是有类型的，编辑器不报红：

本项目实际生成的 `components.d.ts`（节选）：

```ts
declare module 'vue' {
  export interface GlobalComponents {
    ElButton: (typeof import('element-plus/es'))['ElButton']
    IconEpEdit: (typeof import('~icons/ep/edit'))['default']
    IconEpSearch: (typeof import('~icons/ep/search'))['default']
    IconMdiAccount: (typeof import('~icons/mdi/account'))['default']
    IconMdiHome: (typeof import('~icons/mdi/home'))['default']
    MockTest: (typeof import('./src/components/MockTest.vue'))['default']
    // ...项目内组件也会自动进这里
  }
}
```

> 注：`auto-imports.d.ts` 负责 `<script>` 里的函数（如 `ElMessage`、`ref`）。本仓库当前该文件为空，是因为**API 级别我们仍保持显式 `import`（更可控、更易追踪来源）**，只有**组件 / 图标**走自动导入。若你在组件里直接写 `ElMessage.success()` 而不 `import`，插件就会自动补进去并写入该文件——是否采用 API 自动导入，纯属团队约定，不影响构建结果。

### 2.6 真实使用效果（来自 src/components/IconTest.vue）

```vue
<script setup lang="ts">
// 注意：下面模板里的组件全都没有 import，unplugin 自动引入
</script>

<template>
  <div style="display: flex; gap: 16px">
    <!-- 1. 本地 svg：name = 文件名 -->
    <SvgIcon name="home" />
    <!-- 2. 第三方图标：Icon + 集合(ep/mdi) + 图标名 -->
    <IconEpEdit />
    <IconEpSearch />
    <IconMdiHome />
    <IconMdiAccount />
    <!-- 3. 控制颜色/大小：靠外层 style 的 color / font-size -->
    <IconEpEdit style="color: #f56c6c; font-size: 32px" />
  </div>
</template>
```

### 2.7 为什么用这套自动导入（对比其他方案）

| 方案                                                  | 做法                                    | 缺点                                         |
| ----------------------------------------------------- | --------------------------------------- | -------------------------------------------- |
| 全量引入 `app.use(ElementPlus)`                       | 一次性注册所有组件                      | 未用组件也进 bundle，体积大                  |
| 手动按需 `import { ElButton } from 'element-plus'`    | 每个文件手写                            | 繁琐、易漏、样式要单独引、组件多了心智负担重 |
| **unplugin-auto-import + unplugin-vue-components** ✅ | 编译期按使用自动补 import + 样式 + 类型 | 几乎无缺点，且对 Vue/TS 零侵入               |

**选型理由**：零心智负担（写完即用，不用管 import）、体积最优（真正按需）、还能自动生成类型声明。unplugin 系列是 Vite 时代的事实标准。

## 步骤三：主题定制（Sass + Element 变量覆盖）

### 3.1 做了什么

**它是什么**：Sass（dart-sass）是 **CSS 预处理器**——在原生 CSS 基础上扩展出变量（`$var`）、嵌套、`mixin`、函数、`@use`/`@forward` 模块化等能力，最终编译成普通 CSS。它在项目里的**作用**有两点：(1) 写可复用的样式变量与 `mixin`（见 `variables.scss`）；(2) 配合 Element Plus 的 Sass 设计变量做主题覆盖（见下）。

安装 Sass 编译器（Element Plus 的 `importStyle: 'sass'` 与项目 SCSS 都依赖它）：

```bash
pnpm add -D sass
```

`src/styles/element/index.scss` 用 Sass 的 `@forward ... with` 覆盖 Element Plus 设计变量：

```scss
@forward 'element-plus/theme-chalk/src/common/var.scss' with (
  $colors: (
    'primary': (
      'base': #409eff,
    ),
  )
);
```

`vite.config.ts` 的 `css.preprocessorOptions.scss.additionalData` 把该文件与全局变量**自动注入每个 SCSS 文件**（不用每个文件手写 `@use`）：

```ts
css: {
  preprocessorOptions: {
    scss: {
      additionalData: `
        @use "@/styles/element/index.scss" as *;
        @use "@/styles/variables.scss" as *;
      `,
    },
  },
},
```

`src/styles/variables.scss` 放项目级变量与 mixin：

```scss
$sidebar-width: 210px;
@mixin flex-center {
  display: flex;
  align-items: center;
  justify-content: center;
}
```

### 3.2 为什么用 Sass（对比其他样式方案）

| 方案                    | 现状                                                      | 结论                                                        |
| ----------------------- | --------------------------------------------------------- | ----------------------------------------------------------- |
| **Sass (dart-sass)** ✅ | Element Plus 主题源**就是 Sass**；Vite 原生支持；社区主流 | **与 EP 同源，定制最顺**                                    |
| Less                    | Ant Design 体系常用                                       | 与 EP 主题机制不搭                                          |
| Stylus                  | 语法灵活但社区萎缩、维护放缓                              | 不推荐新项目                                                |
| 原生 CSS 变量           | 运行时切换主题（换肤）强                                  | EP 旧版定制不如 Sass 顺；适合"运行时换肤"而非"编译期定主题" |

**选型理由**：Element Plus 的设计变量本就是 Sass，用 `@forward ... with` 覆盖是官方推荐路径，改主色/圆角只动 `src/styles/element/index.scss` 一处，全局生效。

> 💡 **如需运行时动态换肤 / 暗黑模式**：EP 已用 CSS 变量重构了几乎所有组件（`--el-color-primary` 等），可在编译期 Sass 定基调之上，用 JS 实时改写 `--el-*` 变量叠加，无需动构建配置。官方详见「主题」与「暗黑模式」章节。两种方式**可并存**：Sass 定全站主色，CSS 变量做动态微调。

## 步骤四：图标方案（@element-plus/icons-vue + unplugin-icons + Iconify）

### 4.1 做了什么

**它们是什么**：`Iconify` 是聚合各大图标集（Element 官方 `ep`、Material `mdi` 等上万图标）的"图标数据库"；`unplugin-icons` 是 Vite 插件，把指定图标**按需编译成 Vue 组件**（可改色、可缩放、可 tree-shake）；`@iconify-json/ep`、`@iconify-json/mdi` 是对应图标集的数据包。

安装图标相关依赖（`@element-plus/icons-vue` 已在步骤一装过，这里补齐其余）：

```bash
pnpm add -D unplugin-icons @iconify-json/ep @iconify-json/mdi
```

`vite.config.ts`：

```ts
import Icons from 'unplugin-icons/vite'
import IconsResolver from 'unplugin-icons/resolver'

plugins: [
  AutoImport({ resolvers: [IconsResolver({ prefix: 'Icon', enabledCollections: ['ep', 'mdi'] })] }),
  Components({ resolvers: [IconsResolver({ prefix: 'Icon', enabledCollections: ['ep', 'mdi'] })] }),
  Icons(),
]
```

使用：`<IconEpHome />`、`<IconMdiAccount />` 自动按需引入，无需手写 import（机制见步骤二 2.4）。

### 4.2 为什么这样组合（对比其他图标方案）

| 方案                                | 做法                                                                       | 缺点                                                    |
| ----------------------------------- | -------------------------------------------------------------------------- | ------------------------------------------------------- |
| 只用 `@element-plus/icons-vue` 手动 `import` | 每个 EP 官方图标需手写 `import`                                        | 繁琐，图标一多文件顶部很长；现已可用 `ElementPlusResolver` 自动导入 EP 图标，但仍只限 EP 官方集 |
| 字体图标（iconfont / font-awesome） | 引一坨字体文件，用 class 调用                                              | 体积大、不可 tree-shake、改色/缩放受限、多色图标难做    |
| **unplugin-icons + Iconify** ✅     | 聚合上万图标（含 EP 官方 `ep` 集、Material `mdi` 集），按需编译为 Vue 组件 | 需记集合名（ep/mdi…），但可配 `enabledCollections` 限制 |
| 直接贴 SVG 内联                     | 复制 svg 代码到模板                                                        | 重复、难维护、不可复用                                  |

**选型理由**：Iconify 是"图标界的聚合器"，一套接口取遍各大图标集；`unplugin-icons` 把它们编译成**按需的 Vue 组件**（可改色、可缩放、可 tree-shake），比字体图标轻、比手动 import 省事。

## 步骤五：本地 SVG 组件化（unplugin-svg-component）

### 5.1 做了什么

**它是什么**：Vite 插件，扫描本地 `src/icons` 目录下的 `.svg` 文件，自动生成一个全局 `<SvgIcon>` 组件，让"**文件即图标**"，无需手动 `import`。

安装本地 SVG 组件化插件：

```bash
pnpm add -D unplugin-svg-component
```

`src/icons/` 下放 `.svg` 文件，插件扫描目录生成虚拟模块并注册为全局组件：

```ts
// vite.config.ts
import UnpluginSvgComponent from 'unplugin-svg-component/vite'

UnpluginSvgComponent({
  iconDir: 'src/icons', // 本地 svg 目录
  prefix: '', // 组件前缀，空=直接用文件名
  componentName: 'SvgIcon',
  treeShaking: true,
  dts: true,
})
```

```ts
// main.ts
import SvgIcon from '~virtual/svg-component' // 插件生成的虚拟模块
app.component('SvgIcon', SvgIcon) // 注册全局组件
```

模板里用 `<SvgIcon name="home" />`（name = svg 文件名，不含扩展名）。

### 5.2 为什么用这个插件（对比其他 SVG 方案）

| 方案                          | 做法                                                            | 缺点                                |
| ----------------------------- | --------------------------------------------------------------- | ----------------------------------- |
| `<img src="x.svg">` 内联      | 每次手写路径                                                    | 不能改色、不能按需、DOM 冗余        |
| `vite-svg-loader`             | 导入为 Vue 组件                                                 | 需每个文件手写 `import`，无目录扫描 |
| svg-sprite-loader             | 合并成雪碧图                                                    | Webpack 时代方案，Vite 不友好       |
| **unplugin-svg-component** ✅ | 扫描目录→自动生成全局 `<SvgIcon>` + tree-shaking + 自动 `.d.ts` | 几乎无缺点                          |

**选型理由**：目录即组件、支持 tree-shaking（没用到的 svg 不进包）、自动生成类型声明，最贴合 Vite 工程化。与步骤四的 Iconify 图标**互补**：第三方图标用 Iconify，业务自有图标（logo、特定图示）放 `src/icons`。

## 步骤七：api 业务层（api/user/）

> 通用请求封装位于 `utils/request.ts`（提供带拦截器的 axios 实例 `http`：请求拦截器注入 token、响应拦截器统一剥掉 `response.data` 并做错误提示），其完整实现见源码。本节只讲"发什么请求"。

把"**怎么发请求**"（`utils/request.ts`，通用能力）和"**发什么请求**"（业务）分开：接口路径常量、出入参类型、调用函数集中在 `api/*`，组件只 `import` api，不直接碰 axios。换 baseURL、加通用逻辑只动 `request.ts`；业务接口集中、易检索。

```ts
import http from '@/utils/request'
import type { loginForm, loginResponseData, userResponseData } from './type'

const API = {
  // 注意：本仓库登录接口为 /admin/acl/index/login（非 /user/login），见 swagger doc.json
  LOGIN_URL: '/admin/acl/index/login',
  USERINFO_URL: '/admin/acl/user/info',
} as const   // 字面量类型，编译后零开销（不用 enum）

export const loginAPI = (data: loginForm) =>
  http.post<unknown, loginResponseData>(API.LOGIN_URL, data)

// 获取用户信息：token 由请求拦截器自动注入，故无参
export const userinfoAPI = () => http.get<unknown, userResponseData>(API.USERINFO_URL)
```

`type.ts` 定义出入参类型（编译期校验前后端契约）。

## 附：vite-env.d.ts 的作用

本项目 `src/vite-env.d.ts` 给 TypeScript 补充两类类型，否则 `.env` 变量与静态资源导入会报类型错：

```ts
/// <reference types="vite/client" />

interface ImportMetaEnv {
  readonly VITE_API_BASE_URL: string
  readonly VITE_APP_TITLE: string
}
interface ImportMeta {
  readonly env: ImportMetaEnv
}
```

- `/// <reference types="vite/client" />` 让 `import.meta.env` 被 TS 识别。
- `ImportMetaEnv` 里声明的 `VITE_*` 变量才有类型提示；**只有 `VITE_` 前缀的变量才会被 Vite 暴露到 `import.meta.env`**（这也是 踩坑速查里"env 变量 `undefined`"的根因之一：变量名必须带 `VITE_` 前缀，且 `.d.ts` 里要声明）。

## 踩坑速查

| 问题                    | 原因                                                            | 修复                                                            |
| ----------------------- | --------------------------------------------------------------- | --------------------------------------------------------------- |
| env 变量 `undefined`    | `.env` 名与代码不一致                                           | 统一 `VITE_API_BASE_URL`                                        |
| commit 仍报旧错         | lefthook 的 biome/markdownlint `--write` 改了文件但没重新暂存   | 改完重新 `git add` 再 commit                                    |
| 组件/图标不识别         | resolver 未配或前缀写错                                         | 检查 `ElementPlusResolver` / `IconsResolver({ prefix:'Icon' })` |

## 端到端数据流

```text
组件 → api/user/loginAPI(data)
     → utils/request 请求拦截器（注入 token）
     → axios 发 /admin/acl/index/login
     → 后端返回 { code, data, message }，HTTP 状态恒为 200
     → 响应拦截器解析响应体：code===200 视为成功，返回 res.data；110002/110003 清 token 跳登录
     → 组件拿到 loginResponseData（其 data 字段即业务数据）
```
