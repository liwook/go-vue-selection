# 05. 路由守卫与动态权限路由实现

> 在「静态路由表 + Layout + 递归菜单」骨架上接**鉴权路由**：未登录访问任意页跳 `/login`；登录后按用户 `routes` 动态挂菜单（管理员看全部，普通用户只看商品管理）；刷新权限不丢。

---

## 步骤 0：核心流程与原理（必读，避免改错）

```bash
登录页填账号密码
  └─> userStore.userLogin(form)  ──> POST /api/v1/acl/index/login 拿到 data（token 字符串）
        └─> token 存 pinia + localStorage('TOKEN')
        └─> 跳转 redirect || '/'

路由守卫 beforeEach
  └─> 有 token？
       ├─ 无 token 且不是 /login  ──> 跳 /login?redirect=当前路径
       ├─ 有 token 且去 /login   ──> 重定向到 /
       └─ 有 token 且去其他页：
             ├─ 已加载过用户信息（userStore.userInfo 非 null）→ 直接放行
             └─ 没加载过 ──> await userStore.getUserInfo()
                   ├─ 成功：filterAsyncRoute 算出菜单 + router.addRoute 动态挂载
                   │         └─> return { ...to, replace: true }  // 关键：重新解析一次
                   └─ 失败：logout 清 token，跳 /login
```

**关键点**：动态路由必须在「拿到用户信息之后」用 `router.addRoute` 挂上去，挂完要 `return { ...to, replace: true }` 让路由重新匹配一次，否则首次进动态页面会是白屏/404。

> **⚠️ 落地前须知（本仓库现状）**
>
> 1. **接口走 openapi 客户端**：`src/api/client.ts` 封装 `createClient<paths>`（`baseUrl: '/api'`），类型来自 `src/api/schema.d.ts`。登录入口是 `src/api/index.ts` 的 `login()`。
> 2. **token 用 `Authorization: Bearer <token>` 头**：后端 JWT 中间件只读这个头，本仓库只在 `client`（`openapi-fetch`）里注入，写自定义 `token` 头无效。

## 步骤 1：拆分 `src/router/routes.ts`

把现在的「全部静态」拆成三块。

> **为什么拆三块？**
>
> - `constantRoutes`：不需要权限的页面（登录、首页、大屏、404 页）。任何人都能进，一开始就注册进 router。
> - `asyncRoutes`：需要权限的页面（权限管理、商品管理）。**不能一开始就注册**，否则没登录也能直接访问。登录后按用户权限用 `router.addRoute` 挂上。
> - `anyRoute`：404 兜底通配。**必须放最后 addRoute**。如果它留在 `constantRoutes` 里，会在动态路由之前把所有未知路径直接重定向到 /404，导致动态页面进不去。
>   **为什么父路由（/acl、/product）这里不给 `name`？**
>   因为本方案的过滤逻辑是「父路由只要还有存活的子项就保留」（见步骤 2），父路由本身不参与名字匹配，所以不需要 `name`。子路由的 `name`（`user`/`role`/...）才是过滤的依据，必须保留。
>   （对比另一种写法：让父路由也出现在后端 `routes` 列表里，那父路由就得有 `name`。本方案更干净——父路由纯粹是个容器，不该为了「被保留」而硬塞进权限列表。）

## 步骤 2：新增 `src/utils/routeFilter.ts`

> **为什么需要这个函数？**
> `asyncRoutes` 定义的是「系统总共能有哪些页面」，但不同用户该看的不同。这函数就是那把「剪刀」：拿后端返回的「能看名单」(`routes`) 去路由表里剪掉对不上的枝叶，产出「当前用户专属的路由树」，同时喂给 `menuRoutes`（菜单显示）和 `router.addRoute`（路由挂载）。前端定义「有哪些能力」，后端决定「谁有哪个」——函数连接两头。
>
> 过滤规则：父路由（`/acl`、`/product`）是容器，有存活子项才保留（故父路由无需 `name`）；叶子路由看 `name` 是否在后端列表里（用 `name` 而非 `path`，因 `path` 混相对/绝对易错）。

```ts
import type { RouteRecordRaw } from 'vue-router'

/**
 * 根据后端返回的 routes（路由名数组）过滤异步路由
 * @param asyncRoute 完整的异步路由表（前端定义：系统有哪些能力）
 * @param routes     后端给的「该用户可访问的路由名」数组
 *                   注意：后端返回的路由名可能是大写（如 'User'），前端定义的 name 是小写（'user'），
 *                   所以匹配前统一转 toLowerCase，避免大小写不一致导致菜单被全过滤掉。
 */
export function filterAsyncRoute(asyncRoute: RouteRecordRaw[], routes: string[]): RouteRecordRaw[] {
  // 统一转小写一次（递归时直接复用，避免每层重复转换），规避「后端大写 / 前端小写」对不上的问题
  const routeNames = routes.map((r) => r.toLowerCase())
  const result: RouteRecordRaw[] = []
  for (const item of asyncRoute) {
    if (item.children && item.children.length > 0) {
      // 父路由：先递归筛儿子，有存活子项才保留（复制父路由并替换 children，不污染原表）
      const filteredChildren = filterAsyncRoute(item.children, routeNames)
      if (filteredChildren.length > 0) {
        result.push({ ...item, children: filteredChildren })
      }
    } else if (routeNames.includes(item.name as string)) {
      // 叶子路由：name（已统一小写）在后端列表里才保留
      result.push(item)
    }
  }
  return result
}
```

## 步骤 3：新增 `src/store/modules/user.ts`

### 3.1 先装 pinia（为什么需要它）

**为什么要用 pinia？** token 和用户信息需要在「路由守卫」「登录页」「菜单组件」之间共享：守卫要判断有没有登录、菜单要根据 `routes` 渲染。这些组件没直接的父子传值关系，用组件 props 传不现实，所以放进一个全局 store。这里用 pinia 来存 `token / userInfo / menuRoutes`。

当前仓库没装 pinia，先安装并在 `main.ts` 的 `mount` 之前注册：

```bash
# 在 apps/web 目录下
pnpm add pinia
```

```ts
// src/main.ts：在 mount 之前注册 pinia
import { createPinia } from 'pinia'
// ...
app.use(router)
app.use(createPinia())
app.mount('#app')
```

### 3.2 写 userStore

store 直接调 openapi 客户端 `client`（`src/api/client.ts`），**类型从 `src/api/schema.d.ts` 自动派生，不手写 interface、也不新增 `api/user.ts`**：

```ts
import { ref, computed } from 'vue'
import { defineStore } from 'pinia'
import type { RouteRecordRaw } from 'vue-router'
import { constantRoutes, asyncRoutes, anyRoute } from '@/router/routes'
import { client } from '@/api/client'
import type { paths } from '@/api/schema'
import { filterAsyncRoute } from '@/utils/routeFilter'
import router from '@/router'

// 从 schema 取「用户信息对象」类型（响应体 data 字段，去掉可能的 null/undefined）
type UserInfo = NonNullable<paths['/api/v1/acl/user/info']['get']['responses'][200]['content']['application/json']['data']>

// 从 localStorage 读已存的 token（刷新页面时不丢登录态）
const getToken = () => localStorage.getItem('TOKEN') || ''

const useUserStore = defineStore('user', () => {
  const token = ref(getToken())
  // userInfo 用 null 表示「未加载」，比空对象 {} as UserInfo 更诚实、判断更可靠
  const userInfo = ref<UserInfo | null>(null)
  const menuRoutes = ref<RouteRecordRaw[]>(constantRoutes)

  // 是否登录：有 token 即登录（token 存 pinia + localStorage，刷新后自动恢复）
  const isLoggedIn = computed(() => !!token.value)

  // 登录：拿 token 字符串，存 pinia + localStorage
  // 入参类型直接从 schema 推导（login 接口的 requestBody），不手写、避免和后端字段不同步
  // 注：client 在失败（网络/HTTP/业务码非 200）时会 throw，故用 try/catch 捕获；
  // 拦截器已统一 ElMessage 提示，这里只负责拒绝对外抛出错误
  const userLogin = async (
    data: paths['/api/v1/acl/index/login']['post']['requestBody']['content']['application/json'],
  ) => {
    try {
      const { data: res } = await client.POST('/v1/acl/index/login', { body: data })
      // res.data 即 token 字符串（HTTP 2xx + 业务码 200 才有值；否则上面已 throw）
      if (!res?.data) return Promise.reject(new Error('登录失败'))
      token.value = res.data
      localStorage.setItem('TOKEN', res.data)
      return 'ok'
    } catch (error) {
      return Promise.reject(error)
    }
  }

  // 获取用户信息：算菜单 + 动态 addRoute
  const getUserInfo = async () => {
    try {
      const { data: res } = await client.GET('/v1/acl/user/info')
      if (!res?.data) return Promise.reject(new Error('获取用户信息失败'))
      userInfo.value = res.data
      // 过滤出当前用户能看的异步路由；菜单 = 常量路由 + 过滤结果
      const userAsyncRoutes = filterAsyncRoute(asyncRoutes, res.data.routes ?? [])
      menuRoutes.value = [...constantRoutes, ...userAsyncRoutes]
      // 动态挂载：每个异步路由 addRoute，最后补 anyRoute 兜底
      userAsyncRoutes.forEach((route) => router.addRoute(route))
      router.addRoute(anyRoute)
      return 'ok'
    } catch (error) {
      return Promise.reject(error)
    }
  }

  // 退出登录：调后端登出接口（失败也不阻塞）→ 清 token/用户信息 → 重载卸载动态路由
  const logout = async () => {
    await client.POST('/v1/acl/index/logout').catch(() => {})
    token.value = ''
    userInfo.value = null
    localStorage.removeItem('TOKEN')
    window.location.reload()
    return 'ok'
  }

  return { token, userInfo, menuRoutes, isLoggedIn, userLogin, getUserInfo, logout }
})

export default useUserStore
```

> **权限数据从哪来（routes 来源）**
> 本仓库直接对接 `apps/server` 真实后端。`res.data.routes` 是后端按当前用户从 `menu` 表查出的「可看路由名数组」：管理员返回全部 `menu.code`，普通用户只返回其角色关联的少量 `code`，具体集合以 `apps/server/init-sql/init.sql` 的 `menu` 表为准。
> `filterAsyncRoute` 只保留前端 `asyncRoutes` 里 `name`（已 `toLowerCase()`）能对上的 `code`，多出来的会被忽略、不影响运行。所以**前端 `asyncRoutes` 子路由的 `name` 必须与 `menu.code` 对应**（菜单管理的 `code` 是 `Permission`，不是 `Menu`）；父路由无需写进 `routes`，靠子项存活。
>
> **要点**
>
> - token 同时存 pinia（运行时用）和 `localStorage`（刷新后恢复），否则刷新会被守卫当成未登录踢回登录页。
> - `userInfo === null` = 未加载；一旦拉取成功即非 null，动态路由也已挂载，守卫据此判断是否需重新拉取（见步骤 4）。也可直接用 `isLoggedIn` 判登录态。
> - 业务报错（code≠200）由 `client.ts` 拦截器统一 `ElMessage` 提示并 **throw**，store 用 `try/catch` 捕获后 `Promise.reject` 对外抛出，业务层（登录页）再 `catch` 提示，不重复弹窗。
> - `client` 当前没注入 token 头，需在步骤 5 补上，否则登录后 info 会被后端 401 拒绝。

## 步骤 4：给 `src/router/index.ts` 加守卫

> **`router.beforeEach` 是什么？**
> 它是 vue-router 的**全局前置守卫**：每次路由「即将跳转、但还没真正跳」时先调用，可拦截导航、决定放行/改道。参数：`to`（目标）、`from`（来源）。`async` 是因为里面要 `await getUserInfo()`。
>
> **用 `return` 返回值控制导航**：`return true` 放行、`return { path }` 改道、`return { ...to, replace: true }` 用新路由表重匹配。
>
> **为什么用 `return { ...to, replace: true }` 而非直接放行？** `getUserInfo` 里刚 `addRoute` 挂上动态路由，直接放行用的是挂载前的路由表，目标页还不存在 → 白屏/404；`replace: true` 会中断当前导航、用新路由表重新匹配一次，动态路由已存在才能正确进入。

```ts
import { createRouter, createWebHashHistory } from 'vue-router'
import { constantRoutes } from '@/router/routes'
import useUserStore from '@/store/modules/user'

const router = createRouter({
  history: createWebHashHistory(),
  routes: constantRoutes,
  scrollBehavior() {
    return { left: 0, top: 0 }
  },
})

// 白名单：不需要 token 也能进的页面
const whiteList = ['/login']

router.beforeEach(async (to) => {
  const userStore = useUserStore()

  // 未登录：白名单放行，否则去登录页并带 redirect（登录完跳回原页）
  if (!userStore.isLoggedIn) {
    return whiteList.includes(to.path) ? true : { path: '/login', query: { redirect: to.path } }
  }

  // 已登录却去登录页 → 直接回首页
  if (to.path === '/login') return { path: '/' }

  // 已登录去其他页：确保用户信息已加载（动态路由依赖它）
  if (userStore.userInfo === null) {
    try {
      await userStore.getUserInfo()
    } catch {
      // 401 已由 client 拦截器清 token 并跳登录页；其余失败也回登录页兜底
      return { path: '/login', query: { redirect: to.path } }
    }
  }
  // 动态路由刚挂上，重新解析一次目标路由（避免白屏/404）
  return { ...to, replace: true }
})

export default router
```

## 步骤 5：注入 token（只用 openapi 客户端 `client.ts`）

> **本仓库只走 `client`（`openapi-fetch`），不再使用 axios（`utils/request.ts` 已废弃删除）**，所以只需在 `client.ts` 一处注入 token 即可，无需再维护 axios 拦截器。

后端 JWT 中间件（`pkg/middlewares/auth.go`）只读标准 `Authorization` 头、按 `Authorization: Bearer <token>` 解析，**不认自定义的 `token` 头**。

`client.ts` 用官方推荐的 **Middleware（`client.use`）** 做三件事：① 注入 `Authorization` 头（否则登录后的 info 等接口会被后端 401 拒绝）；② 处理非 2xx 的 HTTP 错误；③ 处理 HTTP 2xx 但业务 `code ≠ 200` 的情况。

> **方案 B 的关键约定：失败即 throw，业务层用 `try/catch`**
> 第 ③ 件里业务码非 200 时，中间件会 `throw`（而非仅提示）。这样无论失败来自网络、HTTP 还是业务码，`await client.*` 都会抛异常，store 用 `try/catch` 统一兜住（见步骤 3），不会出现"HTTP 200 但业务失败被当成成功"的漏判。全局已 `ElMessage` 提示，业务层无需重复弹窗。（注：日常业务拦截用 Middleware 即可，自定义 `fetch` 留给替换底层请求引擎的特殊场景。）

```ts
import { ElMessage } from 'element-plus'
import createClient from 'openapi-fetch'
import type { paths } from './schema'
import 'element-plus/es/components/message/style/css'

export const client = createClient<paths>({
  baseUrl: '/api',
})

// 1. 认证中间件 —— 注入 Authorization
client.use({
  onRequest({ request }) {
    const token = localStorage.getItem('TOKEN')
    if (token) {
      request.headers.set('Authorization', `Bearer ${token}`)
    }
    return request
  },
})

// 2. 非 2xx HTTP 响应（401 认证失败、500 服务端/数据库异常等）
client.use({
  onResponseError({ response }) {
    // 401：token 失效 → 清登录态并跳登录页
    if (response.status === 401) {
      localStorage.removeItem('TOKEN')
      if (location.pathname !== '/login') {
        ElMessage({ type: 'error', message: '登录已过期，请重新登录' })
        location.href = '/login'
      }
      return response
    }

    // 其他非 2xx：尝试读取后端返回的错误信息
    const ct = response.headers.get('content-type') ?? ''
    if (ct.includes('application/json')) {
      // response 尚未被内部消费，clone 一下更安全，避免影响后续解析
      response.clone().json().then((d: { message?: string }) => {
        ElMessage({ type: 'error', message: d.message ?? `请求失败（${response.status}）` })
      })
    } else {
      ElMessage({ type: 'error', message: `请求失败（${response.status}）` })
    }

    return response
  },
})

// 3. HTTP 2xx 但业务 code ≠ 200 —— 后端约定 { code, message }
// ⚠️ 方案 B：全局已弹窗提示，这里再 throw，让调用方 try/catch 能捕获（避免业务失败被当成功）
client.use({
  onResponse({ response }) {
    const ct = response.headers.get('content-type') ?? ''
    if (!ct.includes('application/json')) return

    // response 内部已消费，必须 clone 才能读
    response.clone().json().then((d: { code?: number; message?: string }) => {
      if (typeof d.code === 'number' && d.code !== 200) {
        ElMessage({ type: 'error', message: d.message ?? '请求失败' })
        // 业务失败抛异常，由调用方 catch 处理
        throw new Error(d.message ?? '请求失败')
      }
    })
  },
})
```

## 步骤 6：最小可用登录页 `src/views/login/index.vue`

用 Element Plus 的 `el-form`（组件已被 `unplugin-vue-components` 自动引入，直接用；`ElMessage` 也自动引入）。

```vue
<template>
  <div class="login_container">
    <el-form ref="loginFormRef" :model="loginForm" :rules="rules" class="login_form">
      <h2 class="title">Vue Admin 登录</h2>
      <el-form-item prop="username">
        <el-input
          v-model="loginForm.username"
          placeholder="用户名（admin / user）"
          :prefix-icon="User"
        />
      </el-form-item>
      <el-form-item prop="password">
        <el-input
          v-model="loginForm.password"
          type="password"
          show-password
          placeholder="密码（111111）"
          :prefix-icon="Lock"
        />
      </el-form-item>
      <el-form-item>
        <el-button type="primary" class="login_btn" :loading="loading" @click="handleLogin">
          登录
        </el-button>
      </el-form-item>
    </el-form>
  </div>
</template>

<script setup lang="ts">
import { ref, reactive } from 'vue'
import { useRoute, useRouter } from 'vue-router'
import { User, Lock } from '@element-plus/icons-vue'
import type { FormInstance, FormRules } from 'element-plus'
import useUserStore from '@/store/modules/user'

const $router = useRouter()
const $route = useRoute()
const userStore = useUserStore()

const loginFormRef = ref<FormInstance>()
const loading = ref(false)
const loginForm = reactive({
  username: 'admin',
  password: '111111',
})

// 表单校验规则

  username: [{ required: true, message: '请输入用户名', trigger: 'blur' }],
  password: [{ required: true, message: '请输入密码', trigger: 'blur' }],
})

const handleLogin = async () => {
  // 先校验表单
  await loginFormRef.value?.validate()
  loading.value = true

    await userStore.userLogin(loginForm)

    // error 默认是 unknown，用 instanceof 收窄后再取 message
    ElMessage.error(error instanceof Error ? error.message : '登录失败')
  } finally {
    loading.value = false
  }
}
</script>
```

## 常见坑（执行时遇到对照）

- **动态页面白屏 / 404**：忘了 `return { ...to, replace: true }`，或 `anyRoute` 没在最后 `addRoute`。
- **菜单显示不对**：后端返回的 `routes` 与前端 `asyncRoutes` 子路由 `name` 对不上（大小写已被 `toLowerCase()` 兜住，所以多是 `name` 本身就写错，如写了前端不存在的 `Home`，或后端 `code` 与前端 `name` 完全不同）。父路由无需写进 `routes`，靠子项存活。
- **`ElMessage` 报未定义**：本项目用 `unplugin` 自动导入，直接在 `<script setup>` 里用即可，不要手动 `import`。
